# MiniSQL V3 剩余功能详细实现与验证技术文档

## 1. 文档目的

本文针对《MiniSQL数据库管理系统完整详细需求规格说明书 V3》当前尚未完成或仅部分完成的功能，给出可直接执行的实现方案、模块边界、数据流、接口设计、异常语义、验证用例和完成判据。

本文以当前代码状态为基线：

- C++ 编译器、计划器、执行器、页式存储、目录、事务、WAL 和 React 工作台已经形成可运行链路。
- `RIGHT JOIN`、`FULL JOIN`、值列表 `IN/NOT IN`、`EXPLAIN`、只读 `EXPLAIN ANALYZE`、缓冲池统计和 LRU/FIFO 操作已经补入当前工作区。
- `FLOAT` 已完成行存储层的类型编号和 64 位有限值编码，但 SQL Lexer、Catalog、表达式、聚合和 API 类型契约仍需继续接入。
- 文档中的“完成”必须同时满足代码、成功路径、失败路径、边界路径以及适用的重启、事务、HTTP 或前端验证。

## 3. FLOAT 完整实现

### 3.1 目标与约束

`FLOAT` 使用 IEEE 754 二进制 64 位浮点值，类型编号固定为 `7`。允许有限的正常数、次正规数、正负零、最大有限值和最小有限值；禁止 NaN 和正负无穷进入列、表达式结果或持久化格式。

浮点数与整数、DECIMAL 的混合运算必须显式 `CAST`。这样可以避免隐式精度损失，也保持当前 DECIMAL 精确运算规则稳定。

### 3.2 实现步骤

1. Lexer 将普通小数、指数形式和带符号指数识别为 `FLOAT` token，例如 `3.14`、`1.2E-3`。整数仍保持 `INTEGER` token，避免改变 BIGINT 边界解析。
2. Parser 在类型名、字面量和 CAST 目标中增加 `FLOAT`。
3. Catalog 增加 `float` 列定义，并在默认值、CHECK、NOT NULL、唯一约束和外键兼容性检查中使用同一类型标签。
4. 表达式类型检查增加 `FLOAT`，浮点加减乘除、比较和一元正负号统一检查 `std::isfinite`。
5. Value、JSON wire 格式和前端 `Cell` 增加有限浮点值表示；输出时禁止将非有限值序列化为 JSON 非标准数字。
6. 聚合实现 `SUM`、`AVG`、`MIN`、`MAX` 的浮点路径。空输入和全 NULL 仍遵循现有聚合规则，溢出或非有限结果必须返回诊断。
7. 存储层继续使用稳定类型描述符、64 位 little-endian bit pattern 和 NULL 位图。读取时检查字节完整性、类型编号和有限性。

### 3.3 验证设计

应新增 `tests/float-process.mjs` 和底层 FLOAT codec 检查：

- 建表、插入、查询、UPDATE、重启后读取。
- `0.0`、`-0.0`、最大有限值、最小有限值、次正规数、指数形式。
- NaN、Infinity、-Infinity、溢出和截断页拒绝。
- FLOAT 与 INT/DECIMAL 的隐式混合拒绝，显式 CAST 成功。
- FLOAT 聚合、NULL、GROUP BY、ORDER BY 和 DISTINCT。
- API 与前端输出保持有限 JSON number 或明确字符串编码。

完成判据：X03 类型专项测试、跨进程持久化测试和 HTTP/工作台结果测试均通过。

## 4. 子查询和作用域

### 4.1 AST 与绑定

在 `Expr` 中增加 `Subquery`、`Exists`、`InSubquery`、`ScalarSubquery` 节点；在 SELECT 的 FROM 项中增加派生表节点。每个查询块拥有独立 Scope，Scope 按“当前块列、当前块表别名、外层相关 Scope”顺序查找。

绑定结果必须保存 relation identity 和 column identity，不能通过把外层列名替换到字符串中实现相关引用。派生表必须有别名，输出列名重复时必须显式报歧义。

### 4.2 语义规则

- `EXISTS` 只关心子查询是否返回至少一行。
- `IN` 子查询只允许单列输出；空集合为 FALSE，有匹配为 TRUE，无匹配但出现 NULL 为 UNKNOWN。
- `NOT IN` 对 IN 结果执行三值逻辑 NOT。
- 标量子查询零行返回 NULL，一行一列返回该值，多行或多列报错。
- 相关子查询每次使用外层当前行绑定；非相关子查询可以在执行前缓存。

### 4.3 计划与执行

先实现正确性优先的 `Apply` 计划：外层产生一行，绑定外层 Row，再执行子计划。随后增加 `SemiJoin`、`AntiJoin` 和去相关优化。子查询包含聚合、DISTINCT、LIMIT 或相关引用时，优化器默认保守处理。

验证应覆盖空集、NULL、别名遮蔽、嵌套三层作用域、标量多行错误、相关条件、UPDATE/DELETE 子查询和事务失败回滚。完成判据为 X09 全部通过，并且优化前后多重集合和错误行为一致。

## 5. 编译器扩展

### 5.1 批量诊断与错误恢复

新增 `collectDiagnostics` 编译选项。Lexer 在字符串、行注释和块注释中维护状态，只在安全边界同步；Parser 在分号、明确语句起点或 EOF 处恢复。每条诊断包含阶段、错误码、源码范围、实际 Token、期望集合、原始片段和建议。

恢复循环必须保证每次循环消耗 Token 或退出，诊断数量设置上限。错误节点只能用于展示，禁止进入语义绑定、计划生成和执行。

验证：一条请求包含多个语法错误时返回多条诊断；字符串内部的分号不能切断语句；未闭合块注释、缺失分号、相似表名/列名和重复错误抑制均有测试。

### 5.2 AST 与 Plan 版本化

统一 JSON 结构：`schemaVersion`、`nodeId`、`kind`、`children`、`sourceSpan`、表达式字段和输出 Schema。`nodeId` 在单份结果中唯一，所有子节点引用必须可解析。

增加 `deserializePlan` 和 `deserializeAst`，读取未知版本时拒绝或执行显式迁移。整数使用无损编码，DECIMAL 使用固定小数字符串，NULL、Unicode 和列身份不得丢失。

验证：序列化后反序列化再序列化应得到稳定规范化 JSON；重复 nodeId、断裂 children、字段缺失、未知版本和非法类型必须拒绝。

## 6. 优化器扩展

### 6.1 列裁剪

从顶层 Project、ORDER BY、GROUP BY、HAVING、JOIN、Filter 和 DML RowId 反向计算必需列。每个裁剪后的 Schema 必须保留列 identity、顺序、类型和输出名。JOIN 键、过滤条件和隐藏 RowId 即使没有出现在最终 SELECT 中也不能删除。

### 6.2 谓词下推

将 AND 拆成独立谓词，计算每个谓词引用的 relation 集合。只引用单侧关系、没有副作用并且不会改变错误时机的谓词才能下推。OR 不直接拆分。LEFT/FULL JOIN 的 ON 与 WHERE 必须分开处理，右侧 WHERE 不能随意改成右表过滤。

### 6.3 固定点与等价性

每条规则注册 ruleId、前置条件、改写函数、后置验证和摘要。固定点循环受迭代数与节点数限制，结构未变化时停止。测试必须比较优化前后的结果、多重集合、NULL 结果和错误行为，而不是只比较返回行数。

### 6.4 统计信息与成本模型

Catalog 增加表行数、页数、列 distinct 数、NULL 比例、统计更新时间和索引信息。估算器至少输出 SeqScan、IndexScan、NestedLoopJoin、HashJoin 和 Sort 的估计页数、行数与成本。

建议固定模型：扫描成本等于页数，过滤估计使用选择率，排序使用行数与对数因子，嵌套循环使用左右估计行数乘积，HashJoin 使用两侧扫描成本之和。缺失统计使用有界默认值，并在 EXPLAIN 中标记估计来源。

验证高/低选择率、空表、统计过期、索引不存在、相同成本确定性选择，以及估计读页和实际读页差距。

## 7. B+ 树索引与 IndexScan

### 7.1 数据结构

索引页使用稳定页类型编号。内部节点保存分隔键和子页指针，叶节点保存排序键、RowId 和相邻叶指针。每个键比较器必须复用 SQL 类型比较器；NULL 是否可索引以及唯一索引的多个 NULL 规则必须固定写入 Catalog。

### 7.2 写路径

INSERT、UPDATE、DELETE 和事务回滚必须同步维护索引。插入触发叶分裂时向上递归分裂；删除导致低于阈值时执行借位或合并。所有索引页变更进入同一 WAL 批次，事务失败不得留下孤立索引项。

### 7.3 查询路径

等值条件选择点查，范围条件选择叶链扫描；无法匹配索引前缀时回退 SeqScan。IndexScan 输出 RowId，再由 Heap 读取行。EXPLAIN 必须显示访问路径和过滤条件。

验证唯一/复合索引、重复键、NULL、范围边界、重启、页分裂、删除合并、UPDATE 键变化、事务回滚和索引损坏拒绝。

## 8. 并发、权限与审计

### 8.1 多会话并发

将 bridge 当前单活动会话模型扩展为 SessionRegistry。每个会话拥有事务状态、快照或锁集合、取消句柄和最后活动时间。推荐先实现两阶段锁：读锁共享、写锁排他，锁升级必须检测冲突；死锁使用等待图检测并回滚受害事务。

若采用 MVCC，则为版本记录增加 begin/end transaction id，读事务使用快照，写冲突在提交阶段检查。两种方案只能选一种作为项目交付方案，并在设计文档中固定。

### 8.2 权限

Catalog 增加用户、角色、角色继承和对象授权。权限检查发生在解析绑定后、计划生成前；错误信息不能泄露无权访问对象的存在。至少覆盖 CONNECT、SELECT、INSERT、UPDATE、DELETE、CREATE 和 DROP。

### 8.3 审计

审计记录包含 sessionId、userId、时间、语句摘要、对象、操作、结果、错误码、影响行数和耗时。密码、完整敏感值和原始密钥不得写入审计。审计自身采用追加文件或系统表，并提供按时间、用户、对象过滤。

验证两个会话读写冲突、死锁回滚、事务隔离、越权拒绝、授权撤销立即生效和审计记录完整性。

## 9. 外部排序、聚合和服务端取消

当内存预算不足时，Sort 将输入拆成有界内存的有序 run，写入临时文件，再执行多路归并。Aggregate 使用分区文件保存分组状态，分区完成后逐个聚合。临时文件必须带 sessionId、查询 id 和校验信息，查询结束或取消时清理。

HTTP bridge 为每个请求绑定 AbortSignal 和 C++ worker 取消令牌。取消时停止读取、终止执行、清理临时资源，并返回明确的 cancelled 状态；写事务取消时必须返回提交状态未知或已回滚，禁止客户端自动重试写入。

验证大结果集、排序/聚合预算超限、取消前后临时文件、连接断开、流式分块、行数上限和服务端资源回收。

## 10. 备份、迁移与恢复

为页文件、目录和 WAL 增加格式版本。备份包含一致性快照、目录版本、页文件校验和 WAL 截止位置。恢复先校验 manifest，再恢复页文件和目录，最后从 WAL 截止位置重做；任何版本不支持时必须明确拒绝。

迁移脚本必须声明源版本、目标版本、可逆性和失败恢复点。迁移不能静默改变列类型、约束或索引定义。

验证备份期间读写一致性、恢复后行数/约束/索引一致、重复恢复幂等、截断 WAL、损坏页、旧版本升级和迁移失败回滚。
