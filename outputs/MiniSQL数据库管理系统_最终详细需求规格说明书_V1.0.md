## 二、项目目标与系统边界

### 2.1、项目目标

MiniSQL 是一个简化版数据库管理系统，不是单独的语法分析作业。系统必须完成以下链路：

1. 将合法 SQL 编译为 Token、AST、语义检查结果和逻辑执行计划。
2. 对非法 SQL 分阶段报告词法、语法或语义错误，并给出位置和原因。
3. 通过页式存储管理数据文件，通过 Buffer Pool 减少重复磁盘读写。
4. 通过执行引擎消费计划，调用存储引擎完成建表、插入、查询和删除。
5. 通过系统目录维护表、列、类型和存储位置等元数据。
6. 提供稳定接口供数据库模块调用，并为索引、事务、并发控制和查询优化保留扩展点。

### 2.2、系统组成

总览课件第 2、17 页将系统划分为三个模块：

| 模块 | 核心能力 |
| --- | --- |
| SQL 编译器 | 词法分析、语法分析、语义分析、执行计划生成 |
| 存储系统 | 页式存储、页分配/释放/读写、LRU/FIFO 缓存、命中统计、文件管理 |
| 数据库引擎 | 执行引擎、存储引擎、系统目录、数据库模块调用接口 |

课件同时列出可选高级能力：事务、并发控制、复杂索引、查询优化、访问控制。这些能力不计入基础验收，不得因为实现它们而削弱基础链路。

### 2.3、分阶段实施

总览课件第 16 页要求按以下顺序实施：

1. 第 1 阶段实现 SQL 编译器：词法分析、语法分析、语义分析。
2. 第 2 阶段实现存储系统：页式存储、缓存管理。
3. 第 3 阶段实现数据库引擎：执行器、存储引擎、系统目录。

三个阶段可以交叉开发和联调，但验收时必须能分别展示模块能力，避免交付一个不可拆分的黑盒程序。

### 2.4、阶段边界

| 阶段 | 包含内容 | 不默认包含内容 |
| --- | --- | --- |
| SQL 编译器 | Lexer、Parser、AST、Catalog 接口、语义检查、计划生成、优化接口、诊断、测试 | 数据页实际读写 |
| 存储系统 | Page、文件管理、Buffer Pool、LRU/FIFO、命中统计、行页映射 | SQL 解析和计划生成 |
| 数据库引擎 | Executor、StorageEngine、CatalogManager、CLI、系统集成 | 事务、并发控制、复杂索引 |
| 系统扩展 | B+ 树、查询优化、访问控制、EXPLAIN、更多 SQL 语法 | 不计入基础验收 |

### 2.5、端到端数据流

系统主线必须保持清晰：

1. CLI 或 API 接收 SQL 文本。
2. Lexer 把字符流转换为带位置信息的 Token 流。
3. Parser 把 Token 流转换为 AST。
4. Semantic Analyzer 结合 Catalog 完成名字绑定和类型检查。
5. Planner 把 AST 转换为逻辑计划。
6. Optimizer 按已启用规则改写计划，并保持语义等价。
7. Executor 自底向上执行计划。
8. StorageEngine 通过 Buffer Pool 读写 Page。
9. 系统目录记录表结构、列结构和存储映射。
10. 系统返回执行结果或诊断信息。

## 三、MiniSQL 语言范围

### 3.1、语句范围

系统必须支持四类 SQL 语句：

| 语句 | 基础形式 | 必要性 |
| --- | --- | --- |
| CREATE TABLE | 定义表名、列名和列类型 | 课件明确，必须支持 |
| INSERT | 指定目标列并插入一行值 | 课件明确，必须支持 |
| SELECT | 指定查询列、数据源和可选 WHERE | 课件明确，必须支持 |
| DELETE | 指定目标表和可选 WHERE | 课件明确，必须支持 |

WHERE 条件、比较运算、AND、OR、NOT 和括号属于必做语言能力。UPDATE、ORDER BY、GROUP BY、JOIN、NULL、更多类型和算术表达式属于扩展能力，不得默认混入基础验收。

### 3.2、类型系统

| 类型 | 定义 |
| --- | --- |
| INT | 有符号整数；项目内必须统一范围，默认可采用 32 位 |
| VARCHAR | 变长字符串；基础语法不强制带长度参数 |
| BOOL | 表达式求值结果类型；不要求作为表列类型暴露 |

基础版不做 INT 与 VARCHAR 的隐式转换。专项课件出现小数常量但没有对应列类型；基础配置遇到小数统一返回词法诊断 LEX_UNSUPPORTED_DECIMAL，启用第十三章数值类型扩展后按该章识别和运算。此处是对课件缺口的项目约定，不把合法小数本身称为普遍非法 SQL。

### 3.3、标识符、关键字与常量

1. SQL 关键字大小写不敏感，`SELECT`、`select`、`SeLeCt` 等价。
2. 标识符以英文字母或下划线开头，后续为字母、数字或下划线。
3. 表名和列名默认大小写不敏感匹配，同时保留原始写法用于诊断。
4. 保留字不得作为未加引号的表名或列名。
5. 字符串使用单引号包围；字符串内连续两个单引号表示一个单引号字符。
6. 字符串内容保持原样；其中的分号、空白和注释标记不得用于切分语句。
7. 支持 `--` 行注释和 `/* ... */` 块注释；基础版不支持嵌套块注释。

### 3.4、表达式

基础表达式支持：

1. 标识符引用。
2. INT 和 VARCHAR 常量。
3. 括号表达式。
4. 比较运算：等于、不等于、大于、大于等于、小于、小于等于。
5. 布尔运算：AND、OR、NOT。

基础版使用 SQL 单等号 `=` 表示等于，`!=` 表示不等于。专项课件第 11 页出现 `==`，与第 9 页清单不一致；默认把完整 `==` 识别为不支持运算符并返回 LEX_UNSUPPORTED_OPERATOR。兼容开关启用时将其规范化为 `=`，原词素保持 `==`，两种配置分别测试。

AND 的结合强度高于 OR；同级 AND、OR 默认左结合；括号显式改变结构。专项课件第 16 页文字写 NOT 高于比较，但其文法使比较先于 NOT 组成表达式，二者存在冲突。本文按该页文法执行：比较高于 NOT，高于 AND，高于 OR；`NOT age = 18` 解析为 `NOT (age = 18)`。不得在实现和测试中同时采用两种优先级。

WHERE 的最终类型必须是 BOOL。基础版不把 INT 或 VARCHAR 自动当作布尔值。

算术表达式属于扩展。若为了复现课件中的 `10 + 8` 常量折叠示例，至少补充整数加法；若加入乘、除、减，必须同步定义优先级、类型、溢出和除零行为。

### 3.5、语句语义

| 语句 | 必须检查 | 计划结果 |
| --- | --- | --- |
| CREATE TABLE | 表不存在、列名不重复、类型有效 | CreateTable |
| INSERT | 表存在、列存在且不重复、列数等于值数、值类型匹配 | Insert |
| SELECT | 表存在、引用列存在、WHERE 为 BOOL | SeqScan、可选 Filter、Project |
| DELETE | 表存在、引用列存在、WHERE 为 BOOL | Delete，必要时包含扫描和过滤 |

INSERT 必须按列清单建立“列到值”的映射，不得默认按表结构原始顺序写入。基础配置要求列清单恰好覆盖全部列，每列出现一次，只插入一行字面量值；省略列清单、缺列、多行 VALUES 在启用相应扩展前拒绝。SELECT 允许重复列并保留输出顺序和重复位置；无 ORDER BY 不承诺行顺序。无 WHERE 的 SELECT 返回全部存活行，无 WHERE 的 DELETE 删除全部存活行但保留表结构。

课件专项第 30 页只列出 CreateTable、Insert、SeqScan、Filter、Project 五类计划节点，但四类 SQL 包含 DELETE。因此 Delete 是四类语句端到端支持的必要补全节点。

## 四、第 1 阶段：SQL 编译器需求

### 4.1、词法分析

#### REQ-LEX-001：输入输出

Lexer 输入为 SQL 源码，输出为 Token 序列。每个 Token 至少包含：

| 字段 | 要求 |
| --- | --- |
| 类别 | 关键字、标识符、常量、运算符、标点或结束符 |
| 原始文本 | 与源码保持一致 |
| 起始行号 | 从 1 开始 |
| 起始列号 | 从 1 开始 |

建议额外保留结束位置、源码偏移和已解析常量值。输入支持多行、多语句；文件输入建议统一使用 UTF-8。

#### REQ-LEX-002：识别规则

1. 跳过空白和注释，同时持续更新行列号。
2. 多字符运算符按最长有效匹配识别，例如先识别 `>=`，再考虑 `>`。
3. 关键字匹配不得把包含关键字前缀的完整标识符拆开，例如 `selection` 不能拆成 `SELECT` 和 `ion`。
4. 关键字与标识符必须在词法阶段正确区分。
5. 输入结束处输出明确的结束 Token，供 Parser 判断语句是否突然结束。

#### REQ-LEX-003：词法错误

以下情况必须产生词法诊断，不得静默截断或崩溃：

1. 非法字符，例如 `@`。
2. 未闭合字符串。
3. 未闭合块注释。
4. 无法表示的整数字面量；带符号边界按第十七章在字面量构造时检查，不能误拒绝最小 INT。
5. 基础版未支持的小数常量。

诊断必须包含错误类型、位置和原因。

### 4.2、语法分析与 AST

#### REQ-PAR-001：分析方式

Parser 可采用递归下降、LL(1) 表驱动或其他可解释方案。若使用工具生成方案，必须能解释文法、状态、冲突和 AST 构造过程，不能仅以调用库作为完成依据。

LL(1) 或递归下降方案不得直接使用左递归文法。若采用左递归文法，必须先消除左递归或改写为循环结构。

#### REQ-PAR-002：文法交付

项目必须交付 `grammar.md`，完整描述：

1. 已支持语句的文法。
2. 表达式优先级和结合性。
3. 可选结构、重复结构和结束符约定。
4. Parser 实现方案与文法的对应关系。
5. 对课件冲突项的最终处理口径。

基础文法必须覆盖四类语句。下列为按专项课件第 15 页补齐 program、id_list、value_list 和有符号整数后的项目文法；花括号表示重复，方括号表示可选，引号内分号才是输入终结符，产生式末尾分号仅为文法分隔记号。

```ebnf
program         -> { statement } EOF ;
// 输入允许零条或多条语句，读到结束标记后完成批量语法分析。
statement       -> create_stmt | insert_stmt | select_stmt | delete_stmt ;
// 根据语句首关键字选择四种语句之一，并生成对应语句节点。
select_stmt     -> SELECT select_list FROM IDENTIFIER where_opt ';' ;
// 查询必须给出投影清单和一个表名，并以输入中的分号结束。
select_list     -> '*' | IDENTIFIER { ',' IDENTIFIER } ;
// 星号表示全部列；其他形式保留列名顺序及重复项。
where_opt       -> WHERE expression | ε ;
// WHERE 可省略；存在时其后必须有完整表达式。
delete_stmt     -> DELETE FROM IDENTIFIER where_opt ';' ;
// 删除与查询使用相同条件规则，没有 WHERE 时选择全部存活记录。
create_stmt     -> CREATE TABLE IDENTIFIER '(' column_defs ')' ';' ;
// 建表接收表名和非空列定义清单，括号及分号必须闭合。
column_defs     -> column_def { ',' column_def } ;
// 至少定义一列，逗号后必须紧跟下一列定义。
column_def      -> IDENTIFIER type ;
// 一列由名字及基础数据类型组成，约束语法由扩展另行启用。
type            -> INT | VARCHAR ;
// 基础表列只允许整数和字符串，BOOL 仅用于表达式结果。
insert_stmt     -> INSERT INTO IDENTIFIER '(' id_list ')' VALUES '(' value_list ')' ';' ;
// 插入显式列清单及一组值，由后续语义分析检查列值对应关系。
id_list         -> IDENTIFIER { ',' IDENTIFIER } ;
// 保留输入列顺序，不在语法阶段自动按表定义重排。
value_list      -> literal { ',' literal } ;
// 基础插入值只接受字面量，不能引用其他列或子查询。
literal         -> [ '+' | '-' ] INTEGER | STRING ;
// 正负号是独立 Token，语法节点组合符号与整数；字符串保持解码后的原值。
```

**干什么的：** 定义基础配置下完整语句的合法结构，包括原课件省略的列清单和值清单规则。**和前后的关系：** Lexer 提供终结符，Parser 按此文法输出 AST，语义分析再验证名字、类型和列数。

表达式文法必须体现优先级；这里将课件的 CONST 细化为前述 literal：

```ebnf
expression   -> or_expr ;
// 表达式从最低优先级 OR 层进入，保证高优先级操作先形成子树。
or_expr      -> and_expr { OR and_expr } ;
// 每个 OR 操作数是完整的 AND 表达式，同层重复项按左结合构树。
and_expr     -> not_expr { AND not_expr } ;
// AND 连接完整的 NOT 表达式，不能把 OR 的右侧提前并入。
not_expr     -> NOT not_expr | comparison ;
// 连续 NOT 递归组合，最内层比较先构造完成再应用逻辑取反。
comparison   -> primary [ comp_op primary ] ;
// 最多出现一次比较运算，因此连续比较不会被误识别为合法链式比较。
primary      -> IDENTIFIER | literal | '(' expression ')' ;
// 基础项允许列引用、字面量及括号中的表达式，类型合法性由语义分析判断。
comp_op      -> '=' | '!=' | '>' | '>=' | '<' | '<=' ;
// 基础比较只接受这六种运算符，兼容双等号需在词法规范化后进入这里。
```

**干什么的：** 固定比较、NOT、AND、OR 的构树顺序。**和前后的关系：** SELECT 和 DELETE 的 WHERE 调用本规则，其输出表达式树交给类型检查和 Filter 计划。

#### REQ-PAR-003：AST 节点

| 节点 | 必需信息 |
| --- | --- |
| CreateTableStmt | 表名、列定义列表、源码位置 |
| InsertStmt | 表名、目标列列表、值列表、源码位置 |
| SelectStmt | 查询列或星号、数据源、可选条件、源码位置 |
| DeleteStmt | 目标表、可选条件、源码位置 |
| BinaryExpr | 操作符、左操作数、右操作数、源码位置 |
| UnaryExpr | 操作符、操作数、源码位置 |
| IdentifierExpr | 原始名字、规范化名字、源码位置 |
| LiteralExpr | 常量类别、原始文本、解析值、源码位置 |

AST 不得只是 Token 列表或打印字符串。它是 Parser、Semantic Analyzer 和 Plan Generator 之间的稳定接口，应预留类型和绑定信息字段。

#### REQ-PAR-004：语法诊断

语法诊断至少包含：

1. 错误位置。
2. 实际 Token。
3. 期望 Token 或期望语法结构。

例如输入 `WHERE age > 18 AND;` 时，应指出 `;` 是意外 Token，并列出期望的 `IDENTIFIER`、`CONST`、`(` 或 `NOT`。

批量编译默认在首个错误处停止，不把失败语句交给语义或计划阶段。

### 4.3、语义分析与 Catalog

#### REQ-SEM-001：Catalog 数据

Catalog 在 SQL 编译器中承担符号表作用，必须记录：

1. 表名。
2. 列名。
3. 列顺序。
4. 列类型。

第 1 阶段 Catalog 可以用结构化内存对象实现；第 3 阶段必须迁移或映射到持久化系统目录。

#### REQ-SEM-002：语义检查

| 检查项 | 要求 |
| --- | --- |
| 表存在性 | INSERT、SELECT、DELETE 引用的表必须存在 |
| 建表冲突 | CREATE TABLE 不得创建已存在的表 |
| 列存在性 | 所有引用列必须属于当前目标表 |
| 重复列 | 建表和 INSERT 列清单不得重复 |
| 类型兼容 | 比较两侧类型必须兼容，基础版不做 INT 与 VARCHAR 隐式转换 |
| 列数检查 | INSERT 目标列数量与值数量必须相等 |
| WHERE 类型 | WHERE 最终类型必须为 BOOL |
| 布尔运算 | AND、OR 要求两个操作数为 BOOL；NOT 要求操作数为 BOOL |

类型规则示例：

| 表达式 | 结果类型 |
| --- | --- |
| INT + INT（启用算术扩展后） | INT |
| INT > INT | BOOL |
| VARCHAR = VARCHAR | BOOL |
| BOOL AND BOOL | BOOL |
| NOT BOOL | BOOL |
| INT + VARCHAR（启用算术扩展后） | ERROR |

类型规则必须集中管理，不得散落在 Parser 或执行引擎的零散 if/else 中。

#### REQ-SEM-003：名字绑定

每个标识符引用必须绑定到 Catalog 中的具体列定义。单表基线中，不允许把另一张表的同名列当作当前表列使用。

未找到列时必须报告 SemanticError，指出 student 表中不存在 score 列，同时附该引用在 SQL 中的行列号。

#### REQ-SEM-004：多语句与目录状态

课件未明确同一批输入中多条 DDL/DML 的生效时机。工程基线如下：

1. compileOnly 模式按顺序在隔离的 Catalog 副本上检查。成功的 CREATE 更新副本，使后续同批 INSERT 可见；不读写真实数据页，不修改正式目录。
2. compileOnly 在首错停止，先前成功结果标记为仅编译成功；整批副本结束后丢弃。
3. executeBatch 模式按顺序编译并执行每条语句。CREATE 执行成功并持久化后，后续语句读取更新后的正式目录。
4. 基础配置首错停止，此前成功执行的语句保留，不宣称整批回滚；失败语句不得登记为成功。
5. 显式事务扩展启用后，事务内行为按第十五章处理。编译成功与执行成功必须用不同状态表达。

### 4.4、逻辑执行计划

#### REQ-PLAN-001：基础算子

| 计划节点 | 作用 |
| --- | --- |
| CreateTable | 请求创建表并登记元数据 |
| Insert | 请求按列映射插入记录 |
| SeqScan | 顺序扫描目标表 |
| Filter | 按布尔条件过滤记录 |
| Project | 按指定顺序输出列 |
| Delete | 删除满足条件的目标记录 |

课件第 30 页列出前五类节点，Delete 是四类 SQL 范围内的必要工程补全项。

#### REQ-PLAN-002：生成规则

1. 只有语义检查成功的语句才能生成计划。
2. SELECT 根据 FROM 生成扫描，根据 WHERE 生成过滤，根据查询清单生成投影。
3. 无 WHERE 时可不生成 Filter。
4. DELETE 必须保留能标识原始记录的信息，具体采用记录标识还是存储定位引用，由执行与存储接口统一决定。
5. 父节点引用的列必须能从子节点输出中获得。
6. 计划生成阶段不得直接读写数据页。

SELECT 示例：

```sql
SELECT name FROM student WHERE age > 18;
-- 从 student 表筛选 age 大于 18 的行，只返回 name 列，执行器消费的是编译后的计划。
```

**干什么的：** 展示同时使用扫描、过滤、投影的查询。**和前后的关系：** AST 转换为 `Project[name](Filter[age > 18](SeqScan[student]))`，SeqScan 输出完整行，Filter 保留满足条件的行，Project 最后输出 name。

#### REQ-PLAN-003：计划输出

计划必须输出为树形文本、JSON 或 S-expression 中至少一种格式。建议：

1. JSON 作为机器接口。
2. 树形文本作为人工检查和答辩演示格式。
3. 输出必须明确节点顺序、父子关系和输出列身份。

### 4.5、优化

#### REQ-OPT-001：优化原则

1. 优化必须发生在语义检查之后。
2. 优化不得掩盖非法列引用或类型错误。
3. 优化必须保持结果值、重复行、输出列顺序和必要错误行为一致。
4. 重复执行优化规则必须稳定终止。
5. 必须能展示优化前后的计划结构。

#### REQ-OPT-002：规则分级

| 规则 | 基础要求 | 说明 |
| --- | --- | --- |
| 常量折叠 | 建议 | 将已知常量表达式替换为结果；复现课件示例需支持整数加法 |
| 布尔化简 | 建议 | 简化恒真或恒假条件，删除不改变结果的冗余 Filter |
| Projection Pruning | 进阶 | 只保留查询和过滤真正需要的列 |
| Predicate Pushdown | 扩展 | 有 JOIN 或子查询后尽量提前过滤 |
| 冗余节点消除 | 进阶 | 删除 `Project[*]` 或恒真 Filter |

专项课件第 41 页将两条以上优化规则列为进阶。基础版建议至少实现常量比较折叠和布尔化简；正式最低数量以教师确认为准。

课件优化示例（需启用整数加法）：

```sql
SELECT name FROM student WHERE 1 = 1 AND age > 10 + 8;
-- 条件中包含常量比较及常量加法，用于验证优化器能简化条件且保留列引用。
```

**干什么的：** 验证常量折叠与布尔化简组合。**和前后的关系：** 优化前计划为 `Project[name](Filter[1=1 AND age>10+8](SeqScan[student]))`，优化后为 `Project[name](Filter[age>18](SeqScan[student]))`，两份计划分别交给同一执行器作结果对照。

具体变化是将 `1=1` 折叠为内部 TRUE，将 `10+8` 折叠为 18，再消去 TRUE AND。扫描与投影不变；常量比较、加法与布尔化简都必须在类型检查通过后执行。

#### REQ-OPT-003：等价性验证

1. 每条规则必须同时测试结构变化和结果等价性。
2. 有执行引擎时，对同一数据集比较优化前后结果。
3. 无执行引擎时，可使用测试用表达式求值器或计划解释器做小数据对照，并明确这不是完整数据库集成测试。
4. 比较结果时保留重复次数和列顺序。
5. 未定义记录排序的查询按多重集合比较，不要求扫描顺序完全相同。

## 五、第 2 阶段：存储系统需求

### 5.1、页式存储

#### REQ-PAGE-001：页模型

系统必须实现固定大小 Page：

| 项目 | 要求 |
| --- | --- |
| 页大小 | 本文默认固定 4096 字节；建库时记录，重开时不得随配置变化重新解释旧文件 |
| 页编号 | 每个活动页拥有唯一页号；释放复用时必须使旧引用失效 |
| 页数据 | 支持以字节为单位读写 |
| 页状态 | 记录空闲、已使用、脏页等状态 |

页是磁盘 I/O 的最小单位。即使只读取一行，也必须至少读取该行所在的完整页。

#### REQ-PAGE-002：页操作

| 操作 | 要求 |
| --- | --- |
| 分配页 | 从空闲页或文件末尾分配，返回页号 |
| 释放页 | 清空或标记页状态，避免悬空引用 |
| 读页 | 按页号读取完整页数据 |
| 写页 | 将完整页数据写回文件 |
| 脏页标记 | 内存页被修改后必须标记为脏页 |

### 5.2、文件与磁盘组织

#### REQ-FILE-001：文件管理

系统必须实现文件管理模块，至少支持：

1. 创建数据文件。
2. 打开和关闭数据文件。
3. 按页号定位文件偏移。
4. 读取页。
5. 写回页。
6. 扩展文件以容纳新页。

#### REQ-FILE-002：行页映射

存储引擎必须定义：

1. 一行记录如何序列化为字节。
2. 一个页内如何存放多行记录。
3. 行标识如何映射到页号和页内位置。
4. 删除行后页内空间如何复用。

建议基础版采用以下结构：

| 结构 | 内容 |
| --- | --- |
| 页头 | 页号、行数量、空闲空间起点或空闲链表 |
| 行目录 | 每行在页内的偏移和长度 |
| 行数据区 | 实际记录字节 |
| 空闲空间 | 页内尚未使用的部分 |

### 5.3、缓存机制

#### REQ-BUF-001：Buffer Pool

系统必须实现缓冲池：

1. 请求页时优先查内存缓存。
2. 未命中时从文件读取页。
3. 缓存满时按替换策略淘汰页。
4. 脏页淘汰前必须写回磁盘。

#### REQ-BUF-002：替换策略

| 策略 | 要求 |
| --- | --- |
| LRU | 淘汰最长时间未被访问的页 |
| FIFO | 淘汰最早进入缓存的页 |

两种策略应可配置切换，用于实验对比。

#### REQ-BUF-003：命中统计与日志

系统必须记录：

1. 命中次数。
2. 未命中次数。
3. 命中率。
4. 读盘次数。
5. 写盘次数。
6. 淘汰页号。
7. 被替换策略选中的页。

日志格式必须稳定，便于测试和报告分析。

## 六、第 3 阶段：数据库引擎需求

### 6.1、执行引擎

#### REQ-ENG-001：执行算子

执行引擎必须支持课件列出的五类能力：

| 算子 | 要求 |
| --- | --- |
| CreateTable | 根据计划创建表并登记元数据 |
| Insert | 根据列映射写入一行记录 |
| SeqScan | 顺序读取目标表记录 |
| Filter | 对输入记录求值 WHERE 条件并保留满足条件的记录 |
| Project | 按计划输出列顺序构造结果行 |

同时必须执行 Delete 计划。《指导书》正文第 4、5 页明确列出 DELETE 定位删除和四类核心 SQL 的实际执行，不能把它降为后续扩展。删除可用槽位删除标记或物理删除；后续扫描及重启后的扫描均不得返回已删除行。

#### REQ-ENG-002：执行流程

1. 接收 SQL 编译器输出的逻辑计划。
2. 按计划树自底向上执行。
3. SeqScan 从 Buffer Pool 获取页并解码行。
4. Filter 对每行求值布尔表达式。
5. Project 构造最终输出行。
6. Insert 通过存储引擎写入行。
7. CreateTable 创建文件结构并更新系统目录。
8. Delete 先定位满足条件的记录，再请求存储引擎删除或标记删除。

### 6.2、系统目录

#### REQ-CATALOG-001：目录内容

系统目录必须维护：

1. 表标识。
2. 表名。
3. 列名。
4. 列类型。
5. 列顺序。
6. 表对应的数据文件或页范围。

#### REQ-CATALOG-002：作为特殊表存储

总览课件及《指导书》正文第 3、5、7 页要求系统目录作为特殊表，且所有表数据、元数据均经页式存储持久化。因此正式系统目录必须由 StorageEngine 读写目录表的记录页；独立 JSON 文件或仅内存 Map 不能替代最终实现。可以维护内存索引加速查找，但它须能由目录页重建。固定引导页保存目录根位置和格式版本，避免读取目录前又依赖未加载目录的循环。

### 6.3、模块接口

#### REQ-API-001：编译器接口

SQL 编译器必须提供：

1. 编译 SQL 文本。
2. 输出 Token。
3. 输出 AST。
4. 输出语义检查结果。
5. 输出原始逻辑计划。
6. 输出优化后逻辑计划。
7. 输出诊断信息。

模块间必须传递结构化对象，不得通过解析日志获得下一阶段输入。

#### REQ-API-002：存储引擎接口

存储引擎应向上提供：

1. 创建表。
2. 插入行。
3. 全表扫描。
4. 读取页。
5. 写回页。
6. 查询目录。
7. 根据 RowId 删除记录并返回实际删除数。
8. 刷新脏页、关闭数据库、重新打开并重建目录。

#### REQ-API-003：调用关系

数据库模块应通过明确接口调用编译器和存储引擎。课件中的 `SimpleDBMS.execute(sql_text)` 只展示调用位置，不要求照抄其 Python 类名或把 AST 直接交给存储引擎；正式系统应优先交付逻辑计划。

### 6.4、项目结构

总览课件第 18 页给出建议结构。实现语言未最终确认前，按以下模块语义组织源码：

| 模块 | 内部组件 | 责任 |
| --- | --- | --- |
| sql_compiler | lexer、parser、semantic、planner、catalog | SQL 到逻辑计划及诊断 |
| storage | page、buffer、file_manager | 页生命周期、缓存和文件 I/O |
| engine | executor、storage_engine、catalog_manager | 计划执行、行页映射和目录表管理 |
| cli | main | 输入、配置、结果与退出码 |
| tests | test_sql、test_storage、test_db | 编译、存储与完整系统验收 |
| utils | constants、helpers | 公共常量和无模块状态的工具 |

若课程确认使用 Java 或 C++，应保留相同模块边界，并把文件名映射为对应语言的源码组织方式。课件示例代码使用 Python，但课件未显式规定实现语言；正式提交语言以课程通知为准。

## 七、错误诊断与非功能需求

### 7.1、统一诊断字段

| 字段 | 要求 |
| --- | --- |
| 阶段 | 输入、词法、语法、语义、计划、存储或执行错误 |
| 错误码 | 稳定标识，便于测试统计 |
| 位置 | 来源、行号、列号；存储错误可使用页号或行标识 |
| 原因 | 说明非法字符、缺失结构、未找到名字或类型冲突 |
| 实际信息 | 当前 Token、实际类型、页号或名字 |
| 期望信息 | 期望语法、合法类型或合法范围 |

错误不能只输出 ERROR 或堆栈。诊断位置应指向最相关源码：未知列指向该列引用，类型不兼容指向操作符或表达式，缺少结束符指向输入结束处。

### 7.2、非功能要求

1. 空输入、畸形输入和极端嵌套不得导致未处理崩溃或死循环。
2. 建议配置输入长度、Token 数量和嵌套深度上限，并以诊断拒绝超限输入。
3. 成功结果与失败诊断必须明确区分。
4. 未执行阶段显示“未执行”，不得伪造空结果。
5. 构建和测试必须可在干净环境复现。
6. 缓存统计和页操作必须可观测。
7. CLI 的正常结果输出和错误输出分开；成功返回零退出码，失败返回非零退出码。
8. 测试不依赖交互输入、手工确认或图形界面。
9. 实现语言以课程要求为准；未受限时可按团队熟悉度选择，不把 Web 服务或图形界面作为前置条件。

### 13.2、EXT-SQL-001 算术与复杂表达式

来源：专项课件第 6、27、28、33～35、41 页。目标是在 WHERE、扩展投影和 UPDATE 中支持整数加减乘除、一元正负号和括号，不增加字符串隐式拼接。

1. 从高到低固定为一元正负号、乘除、加减、比较、NOT、AND、OR；二元算术左结合，一元操作递归结合。
2. INT 使用 32 位有符号范围。整数除法向零截断；除零、算术溢出及最小整数除以负一均返回执行诊断，不允许回绕。带符号字面量须能表示最小 INT。
3. 所有列和分支先做静态绑定及类型检查；运行时 AND、OR 从左到右短路求值。优化不得改变本应触发或被短路跳过的运行错误。
4. 增加算术 BinaryExpr、UnaryExpr 及统一求值接口。常量折叠遇到会报错的子树时保留该子树，不能在编译阶段提前触发短路分支内的错误。
5. 测试 X01：乘法高于加法、括号覆盖、一元负号、整数边界、除零、错误分支短路、优化前后错误一致性。

示例输入：

```sql
SELECT age + 2 * 3 AS adjusted_age FROM student WHERE NOT age + 1 <= 20;
-- 投影先乘后加，WHERE 先求 age 加一并比较，再对比较结果执行 NOT。
```

**干什么的：** 检查复杂表达式、表达式投影及别名的组合。**和前后的关系：** 需同时启用 EXT-SQL-010，Parser 构造表达式 AST，类型检查得到 INT 投影与 BOOL 条件，计划执行时分别求值。

### 13.3、EXT-SQL-002 NULL 与三值逻辑

来源：专项课件第 6、35 页。启用后 NULL 是缺失值标记，不等同于零、空字符串或字符串 NULL。行格式增加 NULL 位图，Catalog 记录 nullable 属性。

1. 支持 NULL、IS NULL、IS NOT NULL。与 NULL 的普通比较返回 UNKNOWN，WHERE、HAVING、ON 只接受 TRUE；FALSE 和 UNKNOWN 均不满足条件。
2. NOT UNKNOWN 仍为 UNKNOWN；AND 遇 FALSE 为 FALSE，否则含 UNKNOWN 为 UNKNOWN；OR 遇 TRUE 为 TRUE，否则含 UNKNOWN 为 UNKNOWN。短路规则与此真值规则一致。
3. 算术操作有 NULL 输入时输出 NULL；不对 NULL 进行普通整数运算。NOT NULL 列拒绝 NULL。
4. DISTINCT 和分组在各自键位置将多个 NULL 归为同一组；排序本项目默认升序 NULL 最后、降序 NULL 最前，并支持显式 NULLS FIRST/LAST。
5. 测试 X02：NULL 与空字符串区分、完整三值逻辑组合、IS NULL、重启后 NULL、含 NULL 的分组/连接/排序及优化等价性。

### 13.4、EXT-SQL-003 更多数据类型与转换

来源：专项课件第 6、35 页。完整扩展配置定义 BIGINT、DECIMAL(p,s)、FLOAT、BOOL、DATE 和 VARCHAR(n)，各类型应在 Catalog 与磁盘格式中使用稳定类型编号。

| 类型 | 项目行为 | 必测边界 |
| --- | --- | --- |
| BIGINT | 64 位有符号整数，检查越界 | 最小值、最大值和超界输入 |
| DECIMAL(p,s) | 精确十进制，p 范围 1～38，s 范围 0～p；不允许静默丢失小数位 | 精度溢出、尾零、不同小数位运算 |
| FLOAT | 二进制 64 位浮点；输入与运算仅接受有限值，不存储 NaN/无穷 | 指数形式、极小/极大数、溢出 |
| BOOL | TRUE/FALSE 常量和可空布尔列 | 非布尔赋值拒绝、三值运算 |
| DATE | ISO 日期 YYYY-MM-DD，校验实际日历合法性 | 闰日、无效月日、跨年比较 |
| VARCHAR(n) | n 为最大 Unicode 码点数；UTF-8 存储，另受单行字节容量限制 | 中文、空串、超长和多字节边界 |

数值合并默认 INT 可提升到 BIGINT，整数可与 DECIMAL 精确运算；与 FLOAT 混合必须显式 CAST。DECIMAL 加减结果小数位取较大者，乘法取小数位之和，总精度超过 38 时诊断；DECIMAL 除法结果小数位取两侧较大值且至少为 6，采用 HALF_UP 舍入，并记录结果类型。列赋值若需要缩小精度，必须显式 CAST；CAST 可按目标精度执行同一舍入规则。字符串与数值互转只允许 CAST 并检查全串，不得把数字前缀当完整值。

测试 X03：每种类型解析、类型推断、合法/非法 CAST、写读往返和重启；小数 Lexer 不得将 3.14 拆成多个合法整数。以上精确规则是本项目约定，不要求复刻其他 DBMS 的类型提升表。

### 13.5、EXT-SQL-004 UPDATE

来源：指导书正文第 3 页及专项课件第 6、35 页。支持 UPDATE 表名 SET 列名=表达式，允许多个赋值项及可选 WHERE，返回实际匹配并更新的行数。

1. 目标列存在且在赋值清单中不重复；赋值结果类型与列兼容。所有右值都基于同一行的更新前版本计算，不能受 SET 顺序影响。
2. 无 WHERE 时更新全部存活行；有 WHERE 时仅更新条件为 TRUE 的行。生成 UpdateStmt 和 Update 计划，输入保留 RowId。
3. 固定长度和变长记录更新均要维护槽位有效性；行迁移不得导致扫描漏行或同条语句重复更新。
4. 启用约束、索引、事务后，更新必须同步验证约束、移除旧索引项、加入新索引项并记录撤销信息。
5. 测试 X04：列交换、零行命中、全表更新、变长行迁移、类型失败、重启、约束失败和事务回滚。

### 13.6、EXT-SQL-005 ORDER BY 与分页

来源：指导书正文第 3 页及专项课件第 6、35 页；LIMIT/OFFSET 为排序的配套扩展。支持多排序键，各键独立指定 ASC/DESC，默认 ASC。

1. 普通 SELECT 可按源列或投影别名排序；同名歧义报错。带 DISTINCT 时 ORDER BY 必须能由投影结果唯一确定。
2. 类型比较器统一服务过滤、排序、分组和索引。基础字符串使用区分大小写的 Unicode 码点顺序；不得因系统区域设置变化而改变结果。
3. 相同键的行顺序不作保证，要求稳定分页的 SQL 必须补充唯一排序键。NULL 顺序按 EXT-SQL-002。
4. 增加 Sort 和 Limit 计划。LIMIT/OFFSET 接受非负整数；LIMIT 0 返回空结果，超过总行数返回空集。无 ORDER BY 的分页不承诺具体哪几行。
5. 超内存排序由 EXT-SYS-006 处理，不能无界占用内存。测试 X05：混合升降序、相同键、NULL、隐藏排序列、边界分页及重启后显式排序一致。

### 13.7、EXT-SQL-006 GROUP BY 聚合与 HAVING

来源：指导书正文第 3 页及专项课件第 6、35、41 页。GROUP BY 的配套范围为 COUNT、SUM、AVG、MIN、MAX 与 HAVING，不将其仅实现为排序去重。

1. WHERE 在分组前过滤行，Aggregate 按键聚合，HAVING 在聚合后过滤组，再形成投影、去重和排序结果。
2. 未聚合的投影表达式必须是分组键或仅由分组键和常量组成；不允许任意选择组内某行的非分组列。WHERE 不允许聚合函数，同层聚合嵌套也拒绝。
3. COUNT(*) 统计全部行，COUNT(列) 忽略 NULL；其他聚合忽略 NULL。无 GROUP BY 的空输入返回一行：COUNT 为 0，其余为 NULL；有 GROUP BY 的空输入返回零组。
4. COUNT 输出 BIGINT；整数 SUM 以 BIGINT 累加并检查溢出；整数 AVG 输出 DECIMAL(38,6)。DECIMAL/FLOAT 聚合遵循数值扩展规则。NULL 和聚合扩展是完整 GROUP BY 配置的依赖。
5. 增加 AggregateExpr、GroupBy/Having 字段及 Aggregate 计划。测试 X06：多键、空表、全 NULL、非法投影、聚合溢出和 HAVING。

### 13.8、EXT-SQL-007 DISTINCT

来源：专项课件第 40 页现场修改示例。支持 SELECT DISTINCT，对完整投影结果行去重，不是只比较第一列。

1. 保留投影列次序；结果行次序不保证，除非有 ORDER BY。
2. 同一位置的 NULL 视作可归为同一去重键。比较与哈希必须一致，不能因两种编码代表相同数值而残留重复行。
3. 生成 Distinct 计划，并明确位于投影之后、最终排序和 LIMIT 之前。
4. 测试 X07：完全重复行、多列部分相同、NULL、重复投影列、排序及分页组合。

### 13.9、EXT-SQL-008 JOIN 与多表作用域

来源：指导书正文第 3 页及专项课件第 6、35、41 页。支持 INNER JOIN ... ON ...；LEFT JOIN 为完整扩展配置的一部分并依赖 NULL。RIGHT/FULL/NATURAL/USING 不在本轮精确语法清单内，必须明确拒绝。

1. 表和列别名允许限定引用。未限定同名列在多个数据源中出现时报歧义；禁止重复关系别名。支持多个 JOIN 按明确的 AST 顺序组合。
2. INNER JOIN 只输出 ON 为 TRUE 的组合；LEFT JOIN 必须保留左侧无匹配行，并将右侧列补 NULL。ON 过滤和 WHERE 过滤不可互换而改变外连接结果。
3. 增加 JoinStmt 的关系结构或 JoinRelation AST，绑定到 relationId 和 columnId；计划 Join 接收两个子计划，输出有明确来源身份的合并 Schema。
4. 首先以嵌套循环实现正确性；等值连接可增加 HashJoin。哈希键排除普通等值比较中的 NULL；内存不足时回退或分区，不得漏行。重复键必须保留全部组合。
5. 测试 X08：同名列、自连接、空表、多对多重复、左右无匹配、ON 与 WHERE 差别、多级连接、哈希与嵌套循环结果一致。

### 13.10、EXT-SQL-009 子查询

来源：专项课件第 33 页将子查询列为谓词下推适用场景，具体语法为工程扩展。支持 FROM 派生表、WHERE EXISTS、单列 IN 和标量子查询，逐项在配置中声明。

1. FROM 派生表必须有别名；外层只看见派生表输出列。相关子查询按就近作用域绑定，不能以字符串替换外层列。
2. 标量子查询零行返回 NULL，一行一列返回值，多行或多列报错；EXISTS 只判断是否存在行。
3. IN 逐值比较：有匹配为 TRUE，没有匹配且出现 NULL 比较为 UNKNOWN，否则 FALSE；空集合时为 FALSE。NOT IN 必须依照三值逻辑取反。
4. 增加 SubqueryExpr 与 Apply/SemiJoin 等逻辑节点，先用逐外行执行的方案验证，再考虑去相关化。
5. 测试 X09：嵌套作用域、别名遮蔽、标量多行错误、空集、NULL、相关/非相关查询和去相关前后等价性。

### 13.11、EXT-SQL-010 投影表达式与别名

来源：专项课件复杂表达式和可扩展 AST 目标的配套细化。支持 SELECT 表达式 AS 别名及表名 AS 别名，未提供别名时用稳定的表达式显示名。

1. 投影保持输入列表顺序及重复位置。输出同名列允许存在，但经名字再次引用发生歧义时报错。
2. 表别名只在当前查询作用域有效，使用别名后以别名限定列。投影别名在 ORDER BY 可见，在同层 WHERE、ON 中不可见；GROUP BY/HAVING 基线要求重复原表达式。
3. 扩展 Project 输出 Schema，记录表达式、类型、输出名、来源与源码位置，避免只保存字符串名。
4. 测试 X10：重复别名、同名源列、表达式类型、星号展开及 JOIN 后限定星号。

### 13.12、EXT-SQL-011 约束 默认值与插入增强

本项属于“更多类型和语法”的工程补充。支持 NOT NULL、DEFAULT 常量、PRIMARY KEY、UNIQUE，以及省略列清单、多行 VALUES。CHECK 和外键作为本项进一步子能力，启用状态须单独记录。

1. 未指定目标列清单时按 Schema 顺序映射；显式省略某列时先填 DEFAULT，再填允许的 NULL，否则拒绝。不能自动把缺失 INT 填 0。
2. PRIMARY KEY 唯一且非空；UNIQUE 本项目允许多个 NULL。CHECK 接受 TRUE 或 UNKNOWN、拒绝 FALSE，WHERE 与 CHECK 的 NULL 规则不同。
3. 外键目标必须是主键或唯一键，类型兼容；基础参照动作 RESTRICT，父表删改有引用时报错。复合键按整组比较，级联行为须另行开启。
4. 约束由 Catalog 持久化，由写入路径统一执行，INSERT、UPDATE 和索引构建不得绕过。多行 VALUES 为单条语句，启用本项须具备语句级撤销，任一行失败不得只写入前半批。
5. 测试 X11：缺列、默认值、重复键、多 NULL、CHECK 的 UNKNOWN、外键引用和整批失败撤销。

## 十四、编译器与优化扩展详细需求

### 14.1、EXT-CMP-001 错误恢复与智能纠错

来源：指导书正文第 3 页、专项课件第 19、35、41 页。支持 collectDiagnostics 模式，在安全边界恢复以一次报告多个错误，默认执行模式仍首错停止。

1. Lexer 状态区分字符串、行注释、块注释；仅在字符串和注释之外以分号同步。缺失分号可在明确语句起点提示插入，但不得直接改写后执行。
2. Parser 记录当前位置、实际 Token、期望集合、原始片段和后续建议。恢复必须消耗输入或退出，设置诊断数量上限，防止重复报同一错误。
3. 名称拼写建议只从当前可见 Catalog 和作用域取候选；显示候选及原错误，不能把相似名字自动绑定。涉及权限时不得泄露不可见表名。
4. 错误 AST 节点只用于诊断，禁止生成可执行计划。多个错误间有依赖时抑制重复的衍生错误。
5. 测试 X12：多语句多错误、字符串分号、未闭合注释、相似列名、重复报错上限，以及错误之后合法语句可被独立检查。

### 14.2、EXT-CMP-002 可扩展 AST 与 LR 工具方案

来源：专项课件第 19、20、35 页。AST 使用显式节点种类、源码范围、统一访问入口；新语句增加节点时必须同步语义、计划、序列化和测试。Schema 中稳定保存列身份，禁止依赖 Token 的数组位置作为列身份。

采用 LR 或生成器时，交付生成输入文法、工具版本、生成命令、冲突报告及解决说明；工具生成的 Parser 仍输出同一 AST。人工可解释的 FIRST/FOLLOW 或状态/冲突材料按实际方案提供，不要求不同方案都实现。

测试 X13：新增一种表达式后四个阶段均识别；未知节点必须报不支持，不能被默认分支跳过；相同 SQL 经不同受支持 Parser 实现时，规范化 AST 一致。

### 14.3、EXT-CMP-003 AST Plan 序列化与结构展示

来源：专项课件第 30、35、41、42 页。JSON 输出采用 schemaVersion、nodeId、kind、children、表达式字段、输出 Schema、sourceSpan。nodeId 在单份结果内唯一，children 表达依赖；不得仅输出平铺算子名称。

1. 序列化后再读取必须保留语义、列身份、精确整数和 DECIMAL、NULL、Unicode 字符串。未知格式版本拒绝或显式迁移，不能猜测。
2. 提供原始和优化后两套结构及规则记录；机器输出不得混入日志。交互展示可使用可展开的文本树、节点表及前后差异。
3. 本文档仅包含可编辑文字和表格，不附图；项目的 Plan 可视化功能采用文本树或交互节点信息也须揭示父子关系及 Schema。
4. 测试 X14：JSON 往返、重复字段或断裂引用、深层计划、未知版本、字段缺失、输出稳定性。

### 14.4、EXT-OPT-001 规则式优化框架

来源：专项课件第 33～35、41 页。每条规则定义 ruleId、匹配条件、必要类型信息、适用前提、改写和验证后置条件；优化结果记录应用顺序及前后节点摘要。

1. 基础保留常量比较折叠、布尔化简；完整扩展配置增加算术折叠、列裁剪、谓词下推和冗余节点消除。两条以上规则为专项进阶要求，不等于总览全部查询优化都必做。
2. 固定点循环设置轮数和节点数上限；不允许相反规则反复来回改写。用结构摘要检测未变化，达到上限须返回诊断或最后一个已验证计划。
3. 可按规则独立禁用；错误、类型和列绑定不得通过优化逃避检查。UNKNOWN 规则、溢出和短路语义都必须纳入前提。
4. 测试 X15：每条规则命中和不命中、组合规则、重复优化稳定、终止上限及结果/错误等价。

### 14.5、EXT-OPT-002 列裁剪与冗余节点消除

来源：专项课件第 33 页。从顶层所需输出向下计算必需列，必须额外保留 Filter、JOIN、排序、分组、约束和 DELETE/UPDATE 行定位所需数据。裁剪只影响实际可移除的列，不能因 name 未投影就删掉 age 条件。

仅当 Project 真正保持子节点列身份、顺序、类型、输出名时可消除；不能机械删除所有 Project[*]，尤其是 JOIN、别名和隐藏 RowId 存在时。恒真 Filter 可删除；恒假 Filter 可替换为空结果节点，但其上游可能出错或有副作用时必须证明可消除。

测试 X16：SELECT name WHERE age、按未输出列排序、JOIN 键保留、重复投影列、DELETE RowId 和 Project 输出别名不丢失。

### 14.6、EXT-OPT-003 谓词下推与连接改写

来源：指导书正文第 3 页、专项课件第 33、35 页。对 AND 条件拆分后标注每个谓词引用的关系集合；仅引用某侧列且无副作用、不会新增错误的谓词，可在语义等价时下推到该侧。

1. INNER JOIN 可将单侧谓词提前；两侧谓词保留为连接或上层过滤。含 OR 不可直接拆成多个 Filter。
2. LEFT JOIN 的 ON 和 WHERE 分别处理；不得将右侧 WHERE 条件随意移到右表后保留原外连接，从而新增本应被过滤的补 NULL 行。
3. 子查询存在聚合、DISTINCT、LIMIT、相关引用时默认保守保留，只有明示等价规则才能跨越这些节点。
4. 测试 X17：单侧/双侧/OR 条件、外连接未匹配行、NULL、带 LIMIT 派生表，比较优化前后多重集合和错误行为。

### 14.7、EXT-OPT-004 统计信息与简单代价模型

来源：专项课件第 35、41 页。Catalog 记录行数、页数、可用索引、可选列不同值数量及统计更新时间。估算器输出候选计划的预计扫描页数、行数及排序/连接代价；成本系数和估算公式在设计说明中固定，属于工程模型而非实测时间。

生成 SeqScan/IndexScan、NestedLoopJoin/HashJoin 等合法候选，再选估算成本较低者。统计缺失时使用有界默认估计；统计过期只能降低性能，不能改变结果。提供手工刷新统计入口和固定配置，便于复现实验。

测试 X18：选择性高与低的过滤、索引不存在、空表、统计陈旧、相同成本的确定性选择；报告估计与实际读页差距，不编造固定加速倍数。

### 14.8、EXT-OPT-005 EXPLAIN 与执行统计

来源：专项课件第 35、41 页。EXPLAIN SQL 完成编译并返回节点、估计行数、访问路径、过滤条件、输出列和优化规则，不执行目标语句。

EXPLAIN ANALYZE 仅开放只读查询，实际运行后给出实际行数、耗时、循环次数、页命中及读写统计；写语句一律拒绝，避免检查计划时修改数据。若未实现代价模型则明确显示估计不可用，不伪造数值。

测试 X19：EXPLAIN INSERT 后数据未变化、ANALYZE SELECT 的行数准确、写入 ANALYZE 被拒绝、统计字段来源一致。

## 十五、存储与数据库高级扩展详细需求

### 15.1、EXT-SYS-001 B+ 树索引与索引扫描

来源：总览课件第 2、11～12、17 页及专项课件第 35 页。复杂索引作为扩展，支持 CREATE INDEX、DROP INDEX、单列与复合 B+ 树、唯一索引和 IndexScan；其中索引 DDL 是落实索引功能的工程补充。

1. 索引本身以固定页持久化；内部页存分隔键及子页引用，叶页存键和 RowId 并连接叶链。实现查找、插入分裂、删除后的合并或重分配和根变化。
2. 比较规则与语义分析和排序一致；非唯一键用 RowId 区分重复项，复合键按列次序比较。复合索引声明左前缀适用条件，不得对缺失前导键的条件错误宣称精确查找。
3. INSERT、DELETE、UPDATE 及回滚必须维护所有相关索引。索引构建先覆盖既有数据，唯一冲突时不发布半成品索引。
4. IndexScan 支持等值和有界范围查找，仍按需应用剩余 Filter；不覆盖所需列时依 RowId 取完整行。Catalog 保存根页、键列、唯一性和状态。
5. 测试 X20：根分裂、多级树、重复键、范围边界、叶链扫描、删除回收、重启、更新键、构建失败及与 SeqScan 等价。

### 15.2、EXT-SYS-002 事务与原子性

来源：总览课件第 2、17 页。支持 BEGIN、COMMIT、ROLLBACK，每个会话最多一个活动事务；嵌套 BEGIN 报错。普通语句默认自动提交。

1. 明确事务状态 ACTIVE、COMMITTED、ABORTED，失败语句将显式事务标为必须回滚，之后除 ROLLBACK 外拒绝继续写入。
2. COMMIT 成功后改变可恢复；ROLLBACK 撤销该事务的行、索引及必要目录变更。本期若不实现事务化 DDL，须拒绝显式事务中的 CREATE/DROP/ALTER，不能偷偷自动提交。
3. 启用本项必须同时具备 EXT-SYS-003 的恢复日志，以及多会话时的 EXT-SYS-004 隔离机制；只有一个内存备份副本不能宣称满足持久性。
4. 多行 INSERT、UPDATE、DELETE 的约束失败不得留下已提交的部分修改；返回执行失败并明确回滚状态。
5. 测试 X21：提交、回滚、断开会话、事务中间失败、多语句原子性、重复提交拒绝和索引一致性。

### 15.3、EXT-SYS-003 WAL 恢复与检查点

本项是事务、持久化的工程配套，不将其冒充指导书的基础必做恢复算法。支持写前日志 WAL，日志记录包含序号、事务、页/记录定位、可重做/撤销内容及校验信息。

1. 数据脏页写盘前必须先持久化对应日志；COMMIT 返回成功前提交记录必须持久化。操作系统写缓存刷新与文件关闭须区别定义。
2. 重启区分已提交和未提交事务，恢复已提交改变、撤销未提交影响，且重复恢复结果不变。半条日志和损坏校验须受控处理。
3. 检查点记录恢复起点及必要脏页状态；日志回收不得删除仍被未落盘页、活动事务或备份所需的内容。
4. 页撕裂保护采用整页日志或双写等已说明方案；实现范围不足时不得承诺断电一致性。
5. 测试 X22：日志落盘前、数据落盘前、提交记录后、检查点中途四类故障注入；恢复后检查行、目录、索引及再次恢复结果。

### 15.4、EXT-SYS-004 并发控制

来源：总览课件第 2、17 页。支持独立会话、独立事务上下文，并分别保护共享 Catalog、Buffer Pool、页分配器和索引结构。

1. 第一实现选用严格两阶段锁，读写行及必要范围加锁，至事务结束释放；要求可串行化时必须处理范围锁或保守表级锁，不能仅靠行锁宣称无幻读。
2. 死锁检测或锁等待超时可选，但须确定受害事务、完整回滚和释放锁；不能永久等待。
3. Buffer 的 pinCount 只表示页正在使用，不等于事务锁；页内容短时互斥和事务隔离必须分别管理。
4. MVCC 为可替代的进阶实现，需记录版本可见性、提交状态、删除版本和回收水位；快照隔离不能未经证明声称可串行化。两条实现路线不要求同时完成。
5. 测试 X23：并发插入、同一行更新竞争、脏读、不可重复读、范围幻读、死锁、读者与页淘汰并发，按声明隔离级别给出预期。

### 15.5、EXT-SYS-005 访问控制与审计

来源：总览课件第 2、17 页。引入用户、角色、对象权限及会话身份，支持授予和撤销 SELECT、INSERT、UPDATE、DELETE、CREATE 等权限。

1. 默认拒绝未授权操作；API 和 CLI 共用权限检查，不允许绕过 CLI 直接调用执行器取得访问权。SQL 名称解析后按实际对象身份授权。
2. 不以明文保存密码，不在日志输出密码或完整凭据；管理员身份只由初始化过程明确建立。用户提供的表名不可直接拼成文件路径。
3. 系统目录的修改只允许受控内部接口；可见元数据也受权限约束。缓存计划执行前重新验证权限版本，撤权后旧计划不得继续写入。
4. 审计记录会话、主体、操作、对象、结果和时间，敏感值脱敏。测试 X24：角色继承、撤权、未授权访问、跨会话身份、系统表保护和诊断不泄露不可见名称。

## 十七、核心系统可执行契约与边界

### 17.1、REQ-CORE-001 输入资源与数值边界

以下上限是本项目可配置默认值，属于工程基线，不能宣称教师指定性能要求：输入 UTF-8 文件最大 8 MiB，批量语句上限 10000，单标识符 128 个 ASCII 字符，单表最多 128 列，表达式嵌套最大 256，Buffer Pool 默认 64 帧，collectDiagnostics 最多 100 条错误。超过上限必须返回明确诊断，零长度 SQL 或仅注释输入成功返回零条语句。

行列号从 1 开始；CRLF 视为一次换行，单独 CR 和 LF 均换行；TAB 按一个源字符计列，Unicode 字符按码点计列。Token 同时记录起止字节偏移，范围采用包含起点、不包含终点。EOF 位置紧随最后字符。关键字大小写不敏感，但字符串内容不得被整体 upper/lower 操作修改。

整数符号是独立 Token，Lexer 读取非负幅值，Parser 组合字面量符号后检查 INT 范围；2147483648 只允许紧接负号形成最小 INT，正值应报告常量越界。扩展算术的运算溢出属于执行阶段，不能与字面量范围混淆。

### 17.2、REQ-CORE-002 稳定接口契约

接口名称是建议命名，输入输出与副作用为必须契约。文档中的接口可在 Java 中落实为接口及结果对象，核心逻辑不要求 Spring 容器或 Web 服务。

| 接口 | 输入与输出 | 副作用和失败规则 |
| --- | --- | --- |
| compileOnly | SQL、Catalog 快照、featureFlags → 逐语句 Token/AST/Semantic/Plan/diagnostics | 正式目录及数据不改变，首错后阶段标记 skipped |
| executeBatch | SQL、会话、数据库 → 逐语句执行结果 | 顺序执行；基础模式前成功后失败不回滚已完成语句 |
| lookupTable | 规范化名字 → TableSchema 或不存在 | 只读目录视图，返回稳定 tableId/schemaVersion |
| createTable | Schema → tableId | 通过页式目录登记，失败不发布可用但无存储的表 |
| insertRow | tableId、按 Schema 排列的值 → RowId | 检查容量、类型和约束，成功后返回定位 |
| scanRows | tableId → RowId 与 Row 的迭代器 | 遍历所有数据页，跳过删除槽，关闭时释放 pin |
| deleteRow | tableId、RowId → 是否实际删除 | 过期 RowId 拒绝，重复删除不重复计数 |
| allocatePage/freePage | 所属表或 pageId → 页号或状态 | 更新持久化空闲页信息；系统保留页不可释放 |
| readPage/writePage | pageId、可选完整 4096 字节 → 页内容或状态 | 越界、短读、短写、已释放页均诊断 |
| getPage/unpinPage | pageId、访问模式、是否脏 → PageHandle/状态 | pin 期间不可淘汰，所有出口释放 pin |
| flushPage/flushAll | 页或数据库 → 成功/失败 | 脏页完整写盘后清脏；失败保留脏标志 |
| close/open | 数据目录 → 完成/数据库句柄 | 关闭报告刷新失败；打开检查版本和目录并重建缓存 |

所有计划绑定 tableId、columnId 和 schemaVersion。执行时 Schema 版本不匹配应重新编译或返回 PLAN_STALE_SCHEMA，不能按旧列偏移访问新数据。成功 QueryResult 包含输出列名、类型、行；DDL/DML 返回 affectedRows 和命令种类。失败结果不得同时携带 success=true。

### 17.3、REQ-CORE-003 行页布局与生命周期

1. 采用小端整数、UTF-8 字符串和带格式版本的固定页。基础 INT 按 4 字节存储，VARCHAR 先存非负字节长度再存内容；解析须验证每段长度在记录界限内。
2. 页头记录页号、页类型、所属表和空闲边界；槽目录记录偏移、长度、删除状态及代次。RowId 由 pageId、slotId、generation 组成，槽复用递增代次，旧引用不得指向新行。
3. 页压缩可移动行字节，但不能未经映射改变有效槽身份。基础版单行不得跨页；超出页可用空间返回 ROW_TOO_LARGE，完整扩展也只有显式实现溢出页才可解除此限。
4. 数据库使用全局 pageId 空间，元数据保留页、目录页和用户页不得冲突。表对应页集合经目录或可恢复页链持久化；空页只有脱离全部表/索引引用且无 pin 才能回收。
5. freePage 必须同步撤销缓存映射，不能释放后仍把旧脏缓存写回重用页。空闲列表持久化，重启分配不得把仍使用页重新分配。
6. 打开文件时检查页尺寸、版本、长度和页边界。页损坏、非法槽偏移或循环页链应报 STORAGE_CORRUPTION，不能跳过后返回不完整的成功结果。

### 17.4、REQ-CORE-004 缓冲区和统计口径

Buffer Frame 记录 pageId、dirty、pinCount、访问元数据。LRU 以最近成功 getPage 更新次序；FIFO 以加载入缓存次序记录，命中不调整入队时间。替换只从 pinCount 为零的帧选择。全部帧被固定时返回 BUFFER_EXHAUSTED，禁止淘汰正在使用的页或无限自旋。

一次成功缓存查找命中计 hit，首次加载计 miss；预取若实现必须单独计数。命中率为 hit 除以 hit 与 miss 之和，无请求时定义为 0。diskReads/diskWrites 只计成功的完整页 I/O，失败另计 ioErrors；flush 本身不是一次 getPage。每次淘汰记录访问序号、策略、被淘汰页、dirty 及写回结果。

可复现实验采用容量 3、全部 unpin、访问序列 A、B、C、A、D、A，冷启动清零统计：LRU 有 2 次命中和 4 次未命中，加载 D 淘汰 B；FIFO 有 1 次命中和 5 次未命中，加载 D 淘汰 A。基础日志不是事务 WAL，二者不得混用。

### 17.5、REQ-CORE-005 持久化与错误提交边界

完整基础系统要求 CREATE、INSERT、DELETE 成功后，在明确的成功刷新边界将数据页、目录页及分配元数据写回，正常关闭重新打开后结果一致。本文默认写语句成功响应前刷新相关脏页；I/O 失败时返回失败，保留错误状态并停止进一步写入，不能继续将未可靠落盘状态作为成功基础。

基础配置不声称实现断电原子恢复。指导书的重启测试必须完成；崩溃一致性、事务回滚和多页更新原子性由 EXT-SYS-002/003 增强。遇到存储 I/O 失败应记录可能受影响的页和语句状态为 indeterminate，提示重新打开并检查，不能谎称已完全回滚。普通词法、语法、语义错误发生在写入前，必须保证零数据副作用。

### 17.6、REQ-CORE-006 端到端固定验收脚本

在全新测试数据库中按次序执行，测试不得作用于用户已有数据库。

```sql
CREATE TABLE student(id INT, name VARCHAR, age INT);
-- 创建三列表并登记页式系统目录，后续语句使用此表。
INSERT INTO student(id,name,age) VALUES (1,'Alice',20);
-- 插入第一行，为条件查询提供年龄大于 18 的样本。
INSERT INTO student(age,id,name) VALUES (17,2,'Bob');
-- 列顺序与表定义不同，必须重排为 id=2、name=Bob、age=17。
INSERT INTO student(id,name,age) VALUES (3,'Tom''s book',21);
-- 验证字符串中两个单引号解码为一个单引号并正确存储。
SELECT id,name FROM student WHERE age > 18;
-- 应返回 id 为 1 和 3 的两行，未排序时不强制行顺序。
DELETE FROM student WHERE id = 1;
-- 实际删除第一行并返回 affectedRows=1，保留其他行和表结构。
SELECT id,name FROM student;
-- 应返回 id 为 2 和 3 的两行，后续关闭重开仍须得到同样结果。
```

**干什么的：** 同时验证四类核心语句、列映射、转义、过滤和真实删除。**和前后的关系：** 每条语句依次经过编译、计划、执行、页访问；结束后关闭数据库并重新打开，再执行最后一条查询验证目录和数据都已持久化。

补充基础验收：插入数据直至页数超过缓冲帧数两倍并在报告中记录实际行数/字节数，校验所有行及删除子集；不能只用三行演示替代大量数据测试。分别执行未知列、类型错配、值数不等、缺分号和未闭合字符串，核对错误阶段、具体行列及失败前后数据不变。随机选取页检查序列化与删除槽变化。

5. 实现 B+ 树和 IndexScan、统计及代价模型，再加入 EXPLAIN；把性能比较与结果正确性分别记录。
6. 实现 WAL、事务、并发控制和权限，最后验证大数据溢写、备份恢复和 Fuzz。需要多行原子写的扩展须提前满足事务依赖，不能照章节顺序忽略前置条件。

### 18.4、冻结规则与完成判据

需求来源有明确要求的核心能力必须实现；每个已启用扩展必须完成其全部接口和验收，未启用项在 feature-matrix 明示。任何改变语言、默认配置、磁盘格式或错误行为的修改都须同步需求、文法、实现及测试。

最终系统完成的证据是：四类核心 SQL 的真实结果、所有数据与目录的页式持久化、LRU/FIFO 的确定性日志、非法输入的定位诊断、重启后的数据一致、所选扩展的 X 系列测试及可复现的报告。仅展示 Token、AST 或计划，不能代替完整数据库系统验收。
