# MiniSQL V3 最终验收报告（阶段版）

日期：2026-09-10

## 1. 验收结论

本报告是基于当前代码库和本轮实际运行结果的阶段验收报告。成员 C 的 X24、X27 关键实现已进入可复现回归链路，成员 A/B 的派生表、诊断、schema versioning、页级 B+ 树和 WAL/checkpoint 改动也已合并并完成 Windows Release 回归；但 X01-X27 仍存在部分实现项，因此整体结论为：

**V3 开发中，成员 C 阶段交付通过，整体最终验收未通过。**

不能把专项测试通过解释为所有扩展完成，也不能把工作台能展示字段解释为后端能力已经闭合。

## 2. 本轮实现范围

### 2.1 X24 权限与审计

- 访问目录使用页式文件 `access.catalog.pages`，支持版本号、重载和原子写入。
- `createUser`、`dropUser`、`createRole`、`dropRole`、`setPassword`、角色绑定/解绑、`grant`、`revoke` 均先复制、校验、再一次性提交，不保留部分变更。
- HTTP bridge 提供独立用户、角色、密码、角色绑定、授权和撤权端点，并要求 `GRANT` 权限。
- CLI 只通过 HTTP bridge 执行，支持 `--execute`、`--compile`、`--file`、`--user`、`--password`，自动创建和关闭会话。
- 工作台提供用户、角色、会话和审计面板，并在请求中携带当前连接身份。
- C++ `minisql_database.exe` 已直接读取页式访问目录：session 请求和直连命令均校验用户、密码、操作和对象权限；常驻 session 按 `permissionVersion` 热重载，权限变更后不继续使用旧授权快照。

### 2.2 C2 工作台

- 连接配置增加用户和密码，用户身份保存到本地存储并显示在顶栏。
- 会话面板定时刷新活动会话，显示锁等待、持锁状态和当前会话；活动请求支持取消。
- 设置页增加资源预算、备份列表、全量备份和恢复操作入口。
- 不新增 Demo 展示内容，不依赖图片或图片识别能力。
- `tests/c2-dom.cjs` 已通过真实 Edge 无头浏览器回归，覆盖连接配置保存/删除/连接测试失败与恢复、密码不落盘、身份请求头、权限/审计/会话页签、设置页字段、侧栏边界拖动和 390px 视口无横向溢出。
- `tests/c2-resilience-dom.cjs` 已通过隔离数据库上的真实 Edge 无头浏览器回归，覆盖成功查询、语义失败、客户端超时、活动请求取消、全量备份、替换恢复、损坏备份失败隔离和恢复后查询；没有使用图片断言。

### 2.3 X27 Fuzz

- `fuzz-state-machine.mjs` 生成受状态约束的 CREATE、INSERT、UPDATE、DELETE、SELECT、事务和索引程序，并支持错误探针。
- `fuzz-state-machine-differential.mjs` 使用真实 C++ session 与 Node `node:sqlite` 做共同子集差分。
- `fuzz-state-machine-long-run.mjs` 使用固定种子 `20260908,42`、每种子 512 步执行长跑；`date-literal-process.mjs` 覆盖 DATE/BOOL 字面量类型、索引更新和 DECIMAL 持久化回归。
- `fuzz-state-machine-crash-recovery.mjs` 使用固定种子 `20260908`、40 步状态机基线，在五个提交阶段注入崩溃并重启；5 个故障点均通过稳定前缀、重复读取一致和恢复后继续提交检查。
- `fuzz-state-machine-pressure.mjs` 使用固定种子 `20260908,42,7,11`，每种子执行 512 步并准备 4096 条压力数据，强制外部排序/聚合溢写，临时文件清理和数据库大小/RSS/耗时采样均通过。
- 评估器对不可比较 SELECT 只验证真实引擎接受性，不误调用空的参考 SQL。
- CI 增加纯 Node 契约、Windows 引擎构建、HTTP 回归、SELECT 差分和状态机差分。
- 失败状态机 artifact 会保存完整 `program`，`FUZZ_STATE_REPLAY` 可以按 artifact 重放并检查故障分类；固定种子语料另有逐文件复现契约。

## 4. 当前边界与风险

1. 访问目录已经是 C++ 可读取的页式文件，并会同步到现有 `PersistentCatalog` 的保留系统堆表；支持语句的 C++ 鉴权已先解析结构化 AST 收集基础表对象，但完整 Catalog 名称绑定仍未闭合，因此 X24 仍只能判定为部分实现。
2. HTTP/CLI 仍以统一轻量扫描作为跨语言兜底；C++ 对当前支持的派生表、子查询、JOIN、外键和索引已使用结构化 AST 收集对象，但 CTE、未限定相关作用域和复杂 SQL 的完整 Catalog 绑定仍未闭合。
3. X27 使用共同支持子集进行差分，固定种子五阶段崩溃恢复组合和 4 种子高压资源回归已经通过；尚未覆盖无限输入和多小时长期资源曲线。
4. 工作台真实浏览器回归已覆盖成功查询、语义失败、客户端超时、活动取消、备份迁移校验成功/失败、备份替换恢复和损坏备份失败隔离。
5. Vite 仍提示单包约 737 kB，属于性能优化项，不阻断当前构建和功能验收。
6. `origin/builder-A`、`origin/builder-b` 的有效提交已进入 `origin/main`；历史 `origin/feature/member-c-x24-x27` 与主线无共同历史，其等价的 rebased C 提交已进入主线，不重复合并。

## 5. 后续验收顺序

1. 在 Windows CI 或本机重新构建 Release，执行包含高压资源回归在内的完整引擎 job，并确认 CI 环境的 Edge、MSVC、vcpkg 和隔离目录条件一致。
2. 由各成员补齐 X01-X23、X25-X26 的组合证据，并把命令、版本、数据库路径和 artifact 写入对应 progress 文档。
3. 补齐 X24 的完整 Catalog AST 对象绑定，以及 X27 的无限输入和多小时资源趋势。
4. 只有当每个 X 编号同时满足代码、接口、成功路径、失败路径以及适用的重启/并发验证时，才将 feature matrix 的状态改为“已实现”。
