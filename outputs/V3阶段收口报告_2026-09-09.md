# MiniSQL V3 阶段收口报告

日期：2026-09-09。

本报告记录本轮阶段交付边界。专项测试通过只证明对应能力，不替代 X01-X27 全量组合验收。

## 本阶段完成

### X22 自动检查点增强

- 保留 `MINISQL_AUTO_CHECKPOINT_WRITES`，新增 `MINISQL_AUTO_CHECKPOINT_WAL_BYTES`、`MINISQL_AUTO_CHECKPOINT_DIRTY_PAGES`、`MINISQL_AUTO_CHECKPOINT_DIRTY_RATIO` 和 `MINISQL_AUTO_CHECKPOINT_INTERVAL_MS`。
- 非事务写入和事务 `COMMIT` 统一在成功提交后评估阈值；事务内多条写语句只在提交时计数。
- 统计接口返回阈值、实际 WAL 大小、当前脏页、累计量、上次检查点时间、自动检查点时间和触发原因。
- 新增 `MINISQL_CRASH_AT`，可在 `prepared`、`published`、`applied-page`、`data-synced` 和 `checkpointed` 阶段强制退出。
- 当前 WAL 在单次提交恢复完成后立即截断，尚不等同于完整 ARIES 或独立 WAL 截止位置语义。

### X25 传输层流式结果

- 新增只读 `POST /api/execute/stream` 和会话版 `POST /api/sessions/:id/execute/stream`。
- 响应格式为 NDJSON：`meta`、逐行 `row` 和 `complete`，错误使用 `error` 帧。
- 写入语句在进入执行器前被拒绝，避免流式响应失败后产生不确定写入。
- Node bridge 在 TCP 写缓冲满时等待 `drain`；客户端断开后停止继续发送，并沿用会话取消和临时文件清理机制。
- React 工作台对单条只读 `SELECT` 使用流式接口，其他编译、事务和写入请求保持原 JSON 契约。
- 当前 C++ 执行器仍先收集完整结果，执行器级迭代和真正背压属于后续。

### 并发与权限阶段基线

- X23 已采用数据库级排他两阶段锁，SessionRegistry 管理多逻辑会话、取消文件、活动时间和锁等待。
- X24 已接入持久化访问目录、用户/角色继承、对象授权、加盐密码、会话身份绑定、元数据过滤和审计过滤。
- X24 已补齐页式访问目录、逐项原子授权接口、权限感知 CLI 和工作台权限/审计/会话面板；仍缺访问目录进入 C++ 内部 Catalog，以及直接二进制入口鉴权。
- C2 浏览器回归已通过，覆盖连接身份、错误恢复、权限/审计/会话、设置、边界拖动和移动端无横向溢出；备份实际替换恢复仍由后端专项测试覆盖。
