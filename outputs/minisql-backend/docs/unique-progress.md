# 单列主键与唯一性约束

日期：2026-09-08，对应 EXT-SQL-011 部分能力。

## 一、实现范围

1. CREATE TABLE 列定义接受 PRIMARY KEY 和 UNIQUE；一个表仅允许一项单列主键。重复声明、多个主键、主键显式声明 NULL、主键默认 NULL 均拒绝。
2. 主键隐含 NOT NULL 并校验唯一性；UNIQUE 允许多个 NULL。VARCHAR 按既有大小写敏感精确字符串比较，BIGINT 保持精确整数，不经浮点转换。
3. 目录列描述符升级为 version=3，增加 primaryKey、unique；继续读取无版本纯类型、v1 可空性、v2 默认值格式。旧表不自动增加约束。AST、计划与 Catalog API 返回约束标志。
4. INSERT 在写入前扫描现有记录并校验候选行。UPDATE 在扫描阶段收集所有最终行的唯一值：未命中行保留原值，命中行检查替换值；全部通过后再执行物理替换。因此最终唯一的键交换允许，更新中产生的重复键在首次物理写入前拒绝。
5. DELETE 后可重新使用原键；DEFAULT 导致与已有记录重复时仍拒绝。缺省列、CAST 和 UPDATE DEFAULT 不能绕过约束。

## 三、限制与剩余目标

此前只有列级单列声明；后续已接通表级复合键，见 composite-key-progress.md。约束命名、CHECK、外键及多行 VALUES 原子撤销仍待实现。不能将键约束测试视为 X11 全部通过。

当前使用全表扫描和内存集合，不使用 B+ 树索引，没有新增并发锁和事务。HTTP 服务自身的串行队列不能防止外部进程并发写同一文件。运行时校验失败可在写入前拒绝，但磁盘错误或崩溃仍可能导致部分物理修改，不能声称已具备崩溃原子性或多进程唯一性保证。
