# 表级复合键实施记录

日期：2026-09-08。对应 EXT-SQL-011 的部分能力。

## 一、语法与约束

1. CREATE TABLE 支持表级 PRIMARY KEY(a,b) 和 UNIQUE(a,b)，列列表保留顺序，允许约束写在列声明之前。列名按现有大小写不敏感规则解析，未知列、键内重复列、空键、多个主键拒绝。
2. 复合主键使所有组成列非空，但不要求各列分别唯一；显式 NULL 声明或 DEFAULT NULL 与主键冲突时拒绝。列级主键与表级主键不能同时声明。
3. 复合 UNIQUE 按整个非空元组判重；任意分量为 NULL 时不参与重复检查。比较采用结构化值数组，不拼接字符串，不将 BIGINT 转浮点数。
4. INSERT 和 UPDATE 共用按键分组的精确集合检查。UPDATE 按最终行集合判重，保留前一阶段的零预检失败写入与合法键交换行为。单列约束仍保留原语义。

## 二、目录和接口

Statement、Catalog Table 与 CREATE 计划均保存 keys 数组，每项为 primary 与有序 columns；AST、计划 JSON 和 Catalog API 同步返回。该数组表示表级约束，列级约束标志仍在 columns 中，消费者不能只看单列 unique 标志推断复合唯一性。

系统表记录原本的表名 VARCHAR 字段现在写版本化 JSON 描述符，包含 version=1、name、keys；旧纯表名格式仍可读取，旧列描述符兼容规则保持不变。所有目录记录编码检查通过后才发布表。复合主键可空性在目录写入前规范化。键定义也计入优化器节点资源预算。
