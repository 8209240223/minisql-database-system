# UPDATE 实现与验证

日期：2026-09-08。对应 V3 EXT-SQL-004、X04，状态为部分完成。

## 一、已实现链路

1. Lexer 新增 UPDATE、SET 关键字；Parser 支持一个或多个赋值及可选 WHERE，AST 单独保存 assignments。
2. 语义分析检查表、目标列、右侧引用、重复赋值、类型一致性及 WHERE 布尔类型。不允许给同一列重复赋值，列名比较不区分大小写。
3. Update 计划保存目标列编号与绑定表达式，输入为 SeqScan 或 Filter。编译可返回 AST、原始和优化计划，不执行更新。
4. 执行器先扫描全部命中行。每项右值都读取旧行，因此列交换不受赋值顺序影响。新行编码检查和表达式求值全部成功后才开始修改。
5. HeapStore.replace 校验旧记录，先插入新记录再移除旧记录，并返回迁移后的 RowRef。变长记录可以迁移到其他页，空旧页按既有回收流程释放。
6. 无 WHERE 更新全表，零命中返回零；值未改变的命中行仍计入 affectedRows。成功返回前刷新页式存储。
7. 工作台对含 UPDATE 或 DELETE 单词的执行批次确认，取消不发送执行请求；编译无需确认。检测偏保守，注释或字符串包含这些单词也可能触发确认，不将此检测当作 SQL 语法验证。

## 二、实际测试

`node tests/update-process.mjs` 的 30 项断言已通过。每次请求均使用新进程重新打开数据库，覆盖建表插入、列交换、全表更新、无命中、除零、溢出、重复目标、类型不匹配、未知表列、非法语法、长 Unicode 字符串迁移与缩短、超长行拒绝、编译无副作用和未改变值的命中计数。

HTTP 回归扩充到 32 项，包含真实更新和随后读取。浏览器 DOM 回归扩充到 10 项，包含取消写入确认后不发请求。原有词法语法 12 项、语义计划 25 项、跨进程持久化 7 项、重新构建后的优化器 100 项检查通过，前端构建通过。没有生成或读取图片。

## 三、剩余约束

1. 预检查保证表达式错误在本语句写入前发现，但不是完整事务。磁盘写失败、进程崩溃或断电可能留下部分更新，甚至新旧记录同时存在。Storage 错误返回 commitState=unknown；不可自动重试写入。
2. 尚无 WAL、事务回滚、唯一/外键约束、索引维护或并发隔离，不能据此宣布 X04 完整验收通过。
3. 待更新行全部暂存内存，尚无资源预算、外存暂存或取消；大表性能与故障注入尚未完成。
4. 当前替换路径会改变 RowRef，未来索引必须同步接收新位置；尚未实现同页原位更新优化。
5. 本轮新增 UPDATE 和 SET 为保留关键字。旧库如果曾使用这些单词作未加引号的表列名，目前没有引用标识符支持，需后续兼容策略，不能声称无条件兼容所有旧 SQL。
