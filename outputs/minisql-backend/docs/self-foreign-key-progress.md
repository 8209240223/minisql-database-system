# 自引用外键实施记录

日期：2026-09-08。对应 EXT-SQL-011 的部分能力，不代表整个扩展验收完成。

## 一、定义与持久化

支持列级 REFERENCES self(column) 与表级 FOREIGN KEY(...) REFERENCES self(...)。名称比较沿用大小写不敏感规则。建表检查先构建完整列结构与主键/唯一键，再解析自引用，因此允许引用后声明的列。未知列、非唯一目标、列数与类型不匹配仍拒绝。

自引用复用既有列描述符 v4、表描述符 v3，不新增磁盘格式。目录重新打开时以当前待加载表作为自身引用目标，不要求该表先进入正式目录。对其他表的引用仍要求目标先存在；多张表之间相互引用和 ALTER TABLE 尚不支持。

## 二、执行规则

1. INSERT 将候选行与已有行一起检查，因此一条新行可以引用自己的主键或唯一键；不能只扫描旧数据后误判引用不存在。
2. UPDATE 和 DELETE 收集候选最终行集，在任何物理替换或删除前检查所有保留行的自引用。父键使用整组键集合匹配，子键含任意 NULL 分量时跳过引用检查。
3. 原有 RESTRICT 继续适用于其他记录：只要其他旧记录正在引用待删除或待改变的键，就拒绝该语句，包括该记录也在本次删除范围内的情况。循环引用需先显式解除，例如把可空引用设为 NULL，再删除；不把整批删除隐式改成级联。
4. 当前记录对自身的引用不通过旧记录检查直接拒绝，而依据候选新状态判定。仅改主键、留下指向旧值的引用会失败；主键与自身引用同步修改可以成功。只有自身引用且无其他记录引用的行可以删除。
5. 区分当前行使用页号、页代次、槽号和槽代次，不能仅比较列值或槽号，避免跨页或槽复用时漏掉其他行。
6. 自引用检查与外部父表检查同时生效；其他表对当前表的引用不因新增自引用能力而跳过。

## 三、测试证据

self-foreign-key-process.mjs 新增用例先在旧程序的自引用建表处失败，再在新程序通过 63 项检查。每次请求启动新进程，验证实际目录重载，不仅是同进程缓存。

覆盖自身插入、非法引用、树状关系、循环引用解除、RESTRICT 整批失败、候选新旧键、复合键、NULL、后声明目标列、BIGINT 默认值、纯编译不建表、外部子表约束，以及 70 条记录跨页存储和 1000 字符变长行更新。

关联回归：复合外键 51 项、重新构建的优化器 151 项通过；HTTP 回归包含自引用建表、只改主键失败、主键及引用同步更新、查询与删除，并已通过。HTTP 证据来自真实后端进程，不是演示引擎。未改变前端布局，也未执行浏览器视觉检查。

## 四、未完成与限制

该实现会在自引用写语句中暂存候选行，并构建键集合；不是磁盘索引或外部内存算法，大表内存治理属于 EXT-SYS-006 后续工作。约束错误发生在物理写入前，但存储故障、进程中断后的整批恢复仍需要事务与 WAL，不能据此声称数据库已具备原子提交。

约束命名后续已接入，见 named-constraint-progress.md；新增名称后表描述符写入 v4，自引用自身未改变存储字段。显式参照动作子句、多行 VALUES 撤销及事务能力仍待完成。本轮不修改用户数据，不生成图片。
