# DECIMAL 列与页式持久化

对应 V3 EXT-SQL-003、EXT-SQL-006 的 DECIMAL 链路。本记录不表示 FLOAT、VARCHAR(n)、全部 X03/X06 或 V3 已完成。后续 BOOL 和 DATE 列增量分别见 bool-progress.md、date-progress.md。

## 一、列定义与赋值

CREATE TABLE 和 CAST 共用参数化类型解析，DECIMAL(p,s) 规范化为小写及无前导零的参数。Catalog 验证 p 在 1 至 38、s 在 0 至 p。系统目录原有版本化列描述保存完整类型字符串，重启时恢复精度、小数位及原有约束；未知或非法类型拒绝恢复。

赋值规则集中在 Catalog：整数可以精确写入 DECIMAL，实际值由执行层检查目标容量；DECIMAL 只能隐式提升到具有足够整数位和小数位的目标列。需要缩小声明容量或小数位时必须显式 CAST，即使某次结果恰好能放下，也不隐式削减声明精度。字符串和 BOOL 不隐式转为 DECIMAL。

执行器在约束检查前将候选值规范化为列的小数位，不舍入。显式 CAST 自行完成允许的舍入，再由赋值检查目标类型。DEFAULT 在建表阶段检查类型及实际容量；NULL、NOT NULL、默认值、主键、UNIQUE、CHECK 和相同类型外键沿用既有契约。固定小数位的规范化保证 1.2 与 1.20 写入同列后不能绕过 UNIQUE。

## 二、行格式

旧类型编号保持 INT=0、VARCHAR=1、BIGINT=2，新增 DECIMAL=3。RowSchema 的列描述增加 precision 和 scale。内存 Value 仍以字符串携带规范化十进制文本，但磁盘格式不是 VARCHAR 文本：DECIMAL 字段固定为 16 字节有符号二进制补码整数系数，采用小端序。小数位来自经过校验的模式描述，不经过 double。

只含旧 INT/VARCHAR/BIGINT 的行继续使用既有 v1/v2 编码，旧数据无需批量重写。含 DECIMAL 的行使用 v3：版本和列数、NULL 位图、每列四字节类型描述、非 NULL 字段载荷。描述的低字节为类型编号，第二字节为精度，第三字节为小数位，最高字节保留为零。非 DECIMAL 列的精度和小数位为零。后续 BOOL 列也采用 v3，不改变已有 DECIMAL 行的字节编码。

v3 的 NULL 行也保存并验证模式描述，不能靠 NULL 绕过精度校验。解码核对版本、列数、NULL 位图填充、每列类型及 p/s、系数范围、字段长度和尾随字节。类型或精度不匹配、截断、无效系数均返回 Storage 错误。旧程序不支持 v3 行，不承诺可降级读取新建 DECIMAL 表。

## 三、执行与恢复

INSERT 多行候选与 UPDATE 候选先规范化并验证，再进入既有写批次。扫描、JOIN、GROUP BY、排序、去重和聚合使用恢复后的列类型，因此 DECIMAL 按数值比较，不按字符串排序。整数 SUM 仍遵守 BIGINT 溢出规则，十进制聚合沿用 decimal-progress.md 的精度契约。

事务日志继续记录完整页映像，不增加独立十进制日志。新增探针用 240 条含 38 位系数的数据跨多个页，在 prepared、published、applied-page、data-synced、checkpointed 五个阶段强制退出；恢复前未发布的批次保持旧值，已发布的批次完整重放，连续两次重开一致。
