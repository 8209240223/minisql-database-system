# INNER JOIN 实现与验证

日期：2026-09-08。对应 EXT-SQL-008 及 EXT-SQL-010 的多表子项，整体仍为部分完成。

## 一、语言和绑定

支持 JOIN 或 INNER JOIN，每个连接必须有 ON，可使用显式或隐式表别名。支持自连接和连续连接，当前单条查询最多 32 个连接。

每个绑定列携带所属关系限定名。未限定列在多个关系中同名时拒绝；重复表别名拒绝；ON 仅能引用左侧已有关系和本次右侧关系，不能引用后面才出现的表。表别名遮蔽真实表名，投影别名不对 ON 开放。

LEFT、RIGHT、FULL、OUTER、CROSS、NATURAL、USING 已保留，但对应语法尚不支持，会拒绝而不是误作为隐式别名执行。与既有关键字扩展相同，旧库使用这些名字作为未引用标识符时需要兼容策略，不能承诺所有旧 SQL 均不受影响。

## 二、计划和执行

1. 左结合构造 NestedLoopJoin，包含两个输入、绑定后的 ON、拼接输出 Schema。单表扫描仍保持本地列编号，连接输出使用当前拼接行的编号。
2. 连接不宣称保留单一 RowId，避免后续错误用于更新或删除定位。WHERE Filter 继承输入的行定位性质。
3. 执行器扫描真实页式存储，嵌套循环遍历左右行组合，按 ON 判断并保留全部重复匹配；之后使用原有过滤、投影、去重、排序和分页。
4. 星号按 FROM/连接顺序展开；限定星号只展开对应关系，普通投影和多个星号可以混用，输出同名列按位置保留。
5. 优化器的既有表达式规则也作用于 ON；不会进行连接重排。编译接口暴露 Join AST 和 NestedLoopJoin 计划，HTTP 能力声明包含 innerJoin。

## 三、实际验证

`node tests/join-process.mjs` 的 69 项检查通过，其中 16 条查询与独立 SQLite 参考引擎比较行和列。覆盖等值/非等值条件、自连接、三表连接、重复匹配、左右空表、恒真/恒假条件、星号、DISTINCT、排序、分页、限定名、前向引用、ON 类型错误、未支持连接语法和除零短路。

单表别名 37 项、词法语法 12 项、语义计划 25 项、UPDATE 30 项回归通过。HTTP 40 项通过，包含真实自连接执行与连接计划返回。浏览器 DOM 13 项通过，实际编译并展示 NestedLoopJoin；没有生成或读取图片。

重新构建的优化器测试共 123 项通过，其中新增 6 项连接查询优化开关前后的结果/错误对照。原固定种子语料 500 次检查通过，报告为 `tests/artifacts/fuzz-Cb1m7X/report.json`；该随机语料不包含 JOIN，连接范围由专项及参考引擎对照负责。

## 四、剩余范围

后续更新：NULL、NOT NULL、LEFT JOIN 和 LEFT OUTER JOIN 已由 null-progress.md 记录实现与专项验证。以下为 INNER JOIN 初版边界，当前状态以新记录和总清单为准。

LEFT JOIN 和 NULL 补齐尚未实现，因此不能判定 X08 全部通过。尚无哈希连接、连接重排、代价模型、谓词下推、外存分块或中间结果字节预算。当前左右输入及连接输出在内存中物化，大表和笛卡尔积增长风险尚未解决，不作为生产级大数据连接交付。

尚无子查询嵌套作用域、相关引用、事务快照隔离或并发连接查询保障。没有 JOIN UPDATE/DELETE 语法。输出列编号仍是计划局部位置，不是持久化全局列身份。
