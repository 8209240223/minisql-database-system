# 工作台查询历史实施记录

日期：2026-09-09。对应 V3 第 19.9 节 REQ-UI-008 的历史记录部分，UI08 整体保持未完成。

## 已实现行为

1. 保存提交的完整 SQL、当前连接名称、演示/真实模式、编译/执行动作、时间、耗时、结果行数与错误摘要。成功/失败文字与来源直接显示在记录中。现有连接固定为 MiniSQL Demo 和 MiniSQL C++，不保存会话 ID、连接凭据或结果数据。
2. 历史按新到旧最多 50 条，使用 localStorage 的 minisql-studio-history-v1 保存。刷新恢复时逐项验证类型、数值范围、唯一 ID 及容量，丢弃不合法记录集合，并只还原允许字段。
3. 单条 SQL 上限 65536 个 UTF-16 单元，保留记录的序列化累计上限 262144 个 UTF-16 单元。不是数据库行数或执行资源上限。达到历史总容量时淘汰较旧记录；超长 SQL 不加入历史并显示提示，不截断 SQL 后让用户重载执行。
4. 按 SQL、连接、来源、动作和错误摘要检索。点击只替换当前编辑器 SQL，不自动连接原连接或执行；当前连接仍由用户明确选择。
5. 清空前确认，清空成功后移除持久化键。存储写入或移除失败时显示警告，不把内存中的变化宣称为已持久化。
6. 移除当前没有实现行为的设置按钮，避免空按钮被误认为可用设置。编辑器偏好、主题、结果上限设置并未因此实现。

## 本轮验证

1. 前端 npm.cmd run test:history：24 项通过，覆盖模式和动作、完整 SQL、允许字段、异常 JSON、重复 ID、非法数值、长度限制、容量淘汰及检索。
2. npm.cmd run test:safety：22 项通过。npm.cmd run build：TypeScript/Vite 通过，仍有约 672 kB 主包的既有分块警告。
3. 全局 Playwright minisql-session-ui.cjs 使用隔离后端，在真实 C++ 执行后核对本地记录来源和错误，切换演示执行，刷新恢复、检索、只载入不新增历史、清空后再次刷新，以及历史存储配额失败提示均通过。
4. 既有事务、选区、文件、标签、错误定位、写入确认与 390px DOM 回归通过。没有生成或识别图片，没有向用户数据库写入测试数据。

## 窄屏历史增量（2026-09-09）

1. 1000px 及以下通过顶栏历史图标打开原生模态对话框，桌面继续使用侧栏；两处复用同一份历史内容与状态，检索、载入及清空不另建分支。
2. 对话框支持关闭按钮与 Escape，关闭后回到入口；载入历史则关闭并将焦点转回 SQL 编辑器，不提交请求、不新增历史。变宽至 1001px 以上自动关闭对话框，恢复桌面侧栏。

4. 全局 Playwright 回归在 320px、390px 核对面板边界、无横向溢出、正反向键盘焦点循环、Escape 与按钮关闭、载入内容及编辑器焦点、历史不变；1024px 核对自动关闭，1440px 继续检索与清空回归。只执行 DOM 和交互检查，无图片。
5. 前端 46 项专项测试通过；TypeScript/Vite 构建通过，主包约 673 kB 的既有警告仍在。本轮不改变后端 SQL、事务或用户数据。
