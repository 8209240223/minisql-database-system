# ORDER BY 实施记录

日期：2026-09-08。对应 EXT-SQL-005 与 EXT-SQL-010 的单表排序、别名部分。

## 实现

ORDER BY 支持表达式及多个键，各键独立 ASC/DESC，默认 ASC。单独别名引用解析到投影表达式；重复别名和别名与不同源列表达式冲突时报语义错误。未知列和非法表达式类型在执行前拒绝。

普通查询需要但未投影的排序键作为内部列追加到 Project；Sort 使用这些键并从最终输出移除内部列。DISTINCT 查询不允许增加隐藏源列，必须找到匹配的投影表达式。Sort 位于 Distinct 之后，Limit 位于 Sort 之后，节点关系和键索引都在计划 JSON 中记录。

使用标准稳定排序，以每个键的值及方向逐项比较，保留全部重复行。稳定排序是当前实现选择，相同排序键仍不保证跨版本的固定顺序；需要稳定分页时应包含唯一排序键。

## 测试

optimizer_contract 联合测试增至 100 项并通过。新增 13 项覆盖混合升降序、未输出的源列、别名表达式、排序后分页、DISTINCT 组合、歧义与未知列拒绝、空结果、计划层级和优化开关等价。

独立编译器重建后 25 项计划回归通过；数据库命令行重建后使用独立进程测试排序分页的持久化查询。

## 未完成

尚无 NULL 排序、NULLS FIRST/LAST、外部排序、内存预算和取消。DISTINCT 的排序表达式目前要求与某项投影绑定结构相同，不支持任意由多个投影列推导的新表达式；后续需扩展输出作用域解析。ORDER BY 内部的复合表达式不展开投影别名，只支持独立别名作为键。

上述限制说明 EXT-SQL-005/X05 尚未整体完成，不能由当前内存排序测试推导全部扩展完成。HTTP 和前端仍未接入这些真实能力。
