# 重做日志与语句自动提交

日期：2026-09-08。对应 EXT-SYS-002、EXT-SYS-003 的部分实现，不是完整事务验收报告。

## 一、提交和恢复契约

1. 批次内的分配、释放、记录和目录修改只进入内存页集合。commit 将最终整页镜像写入数据库旁的 .wal.tmp，校验并同步后发布为 .wal；发布后不可回滚。
2. 提交与启动恢复共用日志验证及重放路径：先完整检查日志长度、记录唯一性、页校验、数据库身份、新增页覆盖与最终文件头，再写数据页，最后写文件头、同步数据库、截断并同步日志。
3. 发布前退出保留旧数据库；发布后退出由下次打开完成重做。恢复中途再次退出可以重复重放。损坏或身份不匹配的日志拒绝恢复，不能静默清除。
4. SQL 每条 CREATE TABLE、INSERT、UPDATE、DELETE 单独提交。提交点前异常恢复页缓存和内存目录；提交点后异常返回 commitState=unknown，当前实例拒绝执行、编译及目录读取，必须重新打开。
5. Storage 类型错误沿用保守的 unknown 响应，不把所有存储异常都断言为已回滚。自动重试写语句仍需避免重复提交。

## 二、文件和资源边界

数据库文件头版本 2 增加 128 位身份；旧版只读打开不迁移，首次写批次用完整临时副本加原子发布升级。表描述符版本与文件头版本互相独立。

.lock 文件由原生独占句柄保护，文件存在不代表锁仍被持有。数据库路径规范化，硬链接拒绝打开。锁仅协调本实现的进程，不保护外部程序直接修改文件。数据库备份不能只复制正在提交的数据文件，备份功能仍待实现。

写集合上限为 16384 个 4096 字节页，约 64 MiB；日志每条记录包含元数据页与镜像页，最大约 128 MiB 加日志头。排序、校验和恢复另有内存开销，并非完整内存治理。

## 三、验证与未完成项

journal-process.mjs 覆盖发布前、发布后、部分页写回、数据同步后及日志截断后的强制进程退出，重复恢复、日志损坏、外来日志、空批次、旧格式迁移、独占锁释放和硬链接拒绝。database_contract 覆盖 SQL 层异常和目录一致性。

这些是 Windows 本机进程故障测试，不是物理断电、网络文件系统或所有硬件缓存配置的耐久性认证。POSIX 实现尚未运行验证。

未完成：行级隔离/MVCC、保存点、独立 WAL 截止位置语义、后台检查点调度、事务溢写和全量 X21/X22 验收。HTTP 跨请求事务见 session-progress.md；多逻辑会话和数据库级排他事务锁见 concurrency-progress.md；显式事务核心见 transaction-progress.md；多行 VALUES 见 multirow-progress.md。现有机制不等同于 ARIES 或 MVCC。
