# 行存储与页式系统目录记录

日期：2026-09-08。对应 V3 第六章和第十七章。本文不宣称 SQL 执行或全部扩展已完成。

## 已实现

1. Row 按版本、列数量、列值编码；INT 固定四字节小端，VARCHAR 为四字节长度加 UTF-8 字节。校验类型、列数、容量、UTF-8、截断及尾部多余字节。
2. HeapStore 通过 BufferPool 插入、逐页扫描、按完整页/槽代次读取和删除；表的空页自动释放。表到页的映射由持久页头 owner 字段重建，页号排序保证扫描遍历稳定。
3. 系统目录使用两个具有固定引导 Schema 的特殊堆表：owner 0 保存 tableId/name/columnCount；owner 1 保存 tableId/ordinal/columnName/type。用户表从 id 2 开始，不使用外部 JSON 元数据文件。
4. PersistentCatalog 重开时扫描目录记录，验证列序号、数量、类型和重复定义，并重建供编译器使用的内存 Catalog。
5. CREATE 先验证全部列和编码容量，写列目录并刷新，再写表目录并刷新，最后发布内存定义。多个列记录避免整张表定义必须塞进单个槽位的限制。

## 已运行验证

tests/heap_catalog_contract.cpp 共 471 次断言通过，其中大量断言为逐行校验，不能当作独立场景数量。实际覆盖行编码往返、嵌入零字节、类型/数量错误、超大记录、非法 UTF-8、截断及多余字节。

集成场景在独立测试目录中建立真实页文件，以容量 2 的缓存写入 300 行，每行包含 80 字节字符串，数据页数超过缓存容量两倍。验证全量载荷后删除偶数 id，刷新并关闭；以 FIFO 重开，表身份、列结构与剩余 150 行正确。随后删除全部行，验证数据页回收、表结构保留、重新插入及旧行引用拒绝。

最后一轮证据目录由测试标准输出给出，位于 tests/artifacts/heap-*。每次测试新建独立目录，不操作用户已有数据库。

## 限制

1. 未接 SQL 执行器、真实 API 会话或工作台对象树；上述是存储与目录接口测试，不是四类 SQL 端到端验收。
2. 表目录最后发布不等于事务原子性；无 WAL，I/O 故障可能留下孤立列记录。重开忽略未发布表的列但保留其 id 分配水位，尚未自动回收孤立元数据。
3. 目前使用固定特殊表编号引导和页头扫描，不提供 DROP/ALTER、索引目录或权限元数据。
4. scan 在回调期间固定当前页；回调应只读，批量删除需先记录匹配行位置再修改。真正的取消、背压与并发游标属于后续工作。
5. 尚无 NULL、更多类型、事务和恢复；完整扩展目标保持不变。CMake 已登记相关库和测试，但完整 CTest 构建未在本轮运行。
