# 算术表达式实施记录

日期：2026-09-08。对应 EXT-SQL-001 与算术常量折叠的部分需求。

## 实现范围

WHERE 支持整数加、减、乘、除、一元正负号和括号。优先级从高到低为一元符号、乘除、加减、比较、NOT、AND、OR。同级二元算术左结合，比较不支持链式写法。

整数运算集中在 common/arithmetic.hpp，先用 64 位中间值计算，再检查 INT32 范围；整数除法向零截断。除零及溢出返回执行诊断并保留操作符行列。静态类型检查先完成，不接受 INT 与 VARCHAR 混合算术。

Parser 新增 addition、multiplication、unary 层；Plan 的算术表达式输出类型为 int。执行器共用受检算术函数，AND/OR 仍从左到右短路。

优化器新增 constant-arithmetic 规则；遇到除零或溢出时保留原子树，不在编译阶段提前触发运行错误。该行为用于保持被短路分支的语义。

## 验证

optimizer_contract 扩展为 51 项检查并通过，其中新增 25 项检查覆盖四则优先级、括号、一元符号、负数除法、INT32 溢出、最小整数除以负一和取负、错误分支短路、常量错误编译不提前失败及优化前后诊断相同。

12 项词法/语法回归与 25 项语义/计划回归重新通过。原先“a+1 语法不支持”的用例已改为真正缺失右操作数的 a+；a+1 可以解析，但单独作为 WHERE 仍因非 BOOL 被语义阶段拒绝。

## 未完成

目前只接入 WHERE，尚无 SELECT 表达式投影、UPDATE 赋值表达式或 INSERT 表达式值；完整 EXT-SQL-001 仍为部分实现。NULL、类型提升、精确小数尚未实现，现有折叠规则不能直接视为已支持这些语义。

下一阶段新增表达式用途时必须继续复用类型与求值规则，并扩展文法交付、源码范围、错误和组合测试，不能只放宽 Parser。
