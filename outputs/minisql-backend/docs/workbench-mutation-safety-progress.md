# 工作台全表写入确认实施记录

对应 V3 第 19.5 节 REQ-UI-004 第 5 项。此记录不表示 UI04 的取消、批次状态等全部验收项完成。

## 行为

1. 工作台使用既有 @codemirror/lang-sql 的 StandardSQL 解析树，检查每条顶层 UPDATE/DELETE 是否有顶层 WHERE。子查询内的 WHERE、字符串与注释内容不作为外层写入保护。
2. 任意一条无 WHERE 的写语句都会在整个批次发出前确认，并显示数量。拒绝后不发送 execute 请求，不执行批次中的前序 INSERT 等语句，不新增执行历史。
3. 带 WHERE 的普通更新/删除不弹此确认。WHERE TRUE 不属于本需求规定的“没有 WHERE”，本次不做条件选择率或危险谓词推断。
4. 编译命令不弹写入确认；选区执行只检查将要提交的选区。CLI/API 保留合法全表写入，不改变服务端执行契约。
5. 解析树存在错误且文本包含写入关键字时保守确认。此功能是交互防误操作，不是权限控制，也不将前端解析器作为自研编译器的语义依据；最终语法与执行以 C++ 后端为准。

## 验证

1. 前端 npm.cmd run test:safety 通过 22 项检查，覆盖多语句、混合批次、大小写、注释、转义字符串、子查询条件和不完整语句。本入口使用 Node 24 的 TypeScript 类型擦除读取纯函数，旧版 Node 尚未验证。
2. npm.cmd run build 通过 TypeScript 和 Vite 构建；主包约 670 kB 的既有分块警告仍未消除。
3. 全局 Playwright minisql-session-ui.cjs 使用隔离 C++ 数据库，通过取消确认后零请求及数据不变、正常 WHERE 无弹窗、字符串与注释无误报、选区快捷执行、确认全表更新等真实交互检查。
4. 原有事务、文件、标签页、错误定位和 390px DOM 回归通过；未生成或识别图片。浏览器脚本仍在用户全局运行目录，工程内可移植浏览器验收入口待补齐。

## 剩余范围

REQ-UI-004 的后端取消确认、大结果流式处理、完整批次状态展示仍未完成。此确认不能替代备份、权限和事务；带 WHERE 的语句也可能影响全表。V3 总体验收继续保持未完成。
